## Problem

Secret values still leak for several spellings, reproduced 2026-10-17 by the epic #47 correctness review on PR #21 (spec #42); items 2–4 also leak identically on main (cbe316f).

1. Escaped quote inside an escaped-quoted value: `{\"password\": \"a\\\" b c\"}` → `{\"password\": \"<redacted>\" b c\"}` (` b c` leaks). Cause: PR `redact.py:67` skips backslash escapes when the opening quote is `\"`.
2. Nested YAML map: `credentials:\n  password: s3cretvalue` → `credentials:\n  <redacted> s3cretvalue`. Cause: separator `\s*` at PR `redact.py:26` crosses the newline, the bare value at `:34`/`:109` swallows the child key, and the child match is skipped at `:96`.
3. Block scalar with indentation indicator: `password: |2\n  s3cretvalue` and `password: >2-\n  s3cretvalue` leave the value visible. Cause: PR `redact.py:32` does not accept YAML's indentation digit.
4. Spaced JDBC parameter: `jdbc:x://h;user=a; password=abc def;db=1` leaks `def`. Cause: PR `redact.py:105` reads to the next `;` only when the key directly follows `;`.

Consequence: secrets reach logs and reports for real config spellings. Depends on the redaction rewrite in #42 landing (build on its single pass); keep #41's linear-time bound.
