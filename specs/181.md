- 2026-11-26 — **Serial #179 → #180** (same URL-credential code in `src/bricksmith/ops/redact.py`).
- 2026-11-26 — **#179 direction.** Accept an empty user (`scheme://:pw@host`) as a credential when an `@` follows in the token; `scheme://:8080`-like text with no `@` stays unchanged.
- 2026-11-26 — **#180 direction (delegated owner — an explicit trade-off of the fail-closed rule).** `scheme://X:Y…@…` is a credential whenever an `@` follows `X:` in the same token, even when `Y` begins with digits; the port guard exempts only a token with NO `@` after the port, or whose only `@`s are `/@` handles (kept from #60's decision). Consequence accepted: a rare credential-less URL with a port AND an address in its path (`http://host:8080/u/bob@x.com`) is now masked as if it held a password — it is indistinguishable from `https://svc:2024/Spring@api.example.com`, and leaking a password is worse than over-masking such a URL. The "unchanged" guarantee becomes: text with no secret key and no `scheme://…:…@` shape is unchanged (fuzz vs origin/main).
- 2026-11-26 — **Tests close the class.** Reviewer reproductions; generated table (empty/non-empty user × digit-first passwords with each of `# ? / @ !` × hosts name/IPv4/[v6]/%2F-socket × with/without port/path/query); exact-output table for credential-less URLs incl. `/@` handles and `scheme://:8080/x`; timed linear test 4k/64k comparing the two sizes. No noqa. pytest `--basetemp /tmp/pytest-<spec>` (literal path).
