## Problem

`ModelStore.log_run` (`src/bricksmith/mlops/store.py`, `_verify_upload`) fails with
`ModelError: model artifact upload returned without persisting N required files` on the free workspace,
although every file was uploaded.

Cause: on this workspace `MlflowClient.list_artifacts(run_id, path)` returns an empty list for every path
of a run whose artifact root is `dbfs:/databricks/mlflow-tracking/...`. `download_artifacts` of the same
paths returns the uploaded bytes. The SDK also logs `Unexpected status resolving file endpoints (403)`.
The verification relies only on listing, so it reports every file as missing.

Reproduction (base `main` 0fe5db8, free context, 2026-11-23): `ModelStore.from_clients(...).log_run(...)`
with a one-file artifact directory raises the error above. A raw `MlflowClient` probe shows `log_artifacts`
and `log_text` followed by `list_artifacts` returning `[]`, while `download_artifacts` returns the content.
This affects `train_model`/`relog_model` and `tests/remote/test_models.py`.

Files: `src/bricksmith/mlops/store.py` (`_verify_upload`), `tests/unit/mlops/` store tests,
`tests/remote/test_models.py`. Open question: whether to fall back to download-based verification
when listing is empty, or whether this is a temporary platform condition.

Unity Catalog registration is affected too: `ModelStore.create_version(name, model, run_id)` fails with
`Unable to download model artifacts from source artifact location 'runs:/<run>/model' ... Failed to download
artifacts from path 'model'`, because the client-side copy to Unity Catalog lists the directory. Registering
any version on the free workspace is therefore unavailable while listing returns nothing (it blocks spec 80
task 3.1, whose proof tags a registered version).
