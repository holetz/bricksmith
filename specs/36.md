## Problem

Two gate tests fail on Windows for reasons unrelated to product behavior:

- tests/test_dist.py::test_built_artifacts_import_without_heavy_integrations fails because scripts/verify_dist.py builds interpreter and console-script paths as `env / "bin" / "python"` and `env / "bin" / "bricksmith"` (lines 49 and 53). Windows virtual environments use `Scripts/python.exe` and `Scripts/bricksmith.exe`.
- tests/unit/io/test_volumes.py::test_filesystem_client_and_symlink_escape fails with OSError at `symlink_to` (line 142) when the process lacks symlink privilege, which is the Windows default without Developer Mode.

## Proposal

Make scripts/verify_dist.py resolve the environment's executable directory portably, using `Scripts` with an `.exe` suffix on Windows and `bin` elsewhere, through one helper so that both the interpreter and the console script use it. In the volumes test, attempt the symlink and `pytest.skip` with an explicit reason when the OS refuses it. Do not weaken the escape assertion where symlinks are available.

## Out of Scope

Changing the volumes client's symlink-escape behavior; changing CI, hooks or the gate command; other platform-specific tests not listed here.

## Impact

scripts/verify_dist.py; tests/unit/io/test_volumes.py. tests/test_dist.py is unchanged unless it duplicates the path logic.

## Validation

On Windows: `uv run pytest tests/test_dist.py tests/unit/io/test_volumes.py -rs` passes, and the symlink test is reported as skipped with its reason when symlink privilege is absent. On Linux, both tests run and pass with no skip. The full gate is green.

## Design

A small helper in scripts/verify_dist.py returns the venv executable directory (`Scripts` on Windows, `bin` elsewhere) and the executable name with `.exe` on Windows; the interpreter and console-script paths both use it. The volumes test wraps `symlink_to` in a try/except OSError and calls `pytest.skip` with the reason.

## Alternatives Considered

- Skip the whole dist test on Windows: rejected, it hides a real portability check.
- Mark the symlink test with a platform skipif: rejected, privilege varies per machine, not per OS.

## Open Decisions

- none — the proposal fixes both behaviors.

## Risks

- A broad OSError catch could mask other failures: limit the try to the `symlink_to` call only.
