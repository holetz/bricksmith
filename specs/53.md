## Problem

The row and Spark quality engines order bounded samples differently, so with a `sample_limit` that truncates they return different rows. Pre-existing on main; reproduced 2026-10-17 by the epic #47 correctness review on PR #20 (spec #46).

Reproduction: `run_check(Check.cardinality('a', expect='many_to_many', require_match=True), …)` with unmatched keys `2` and `10` and `sample_limit=1` returns `({'a': 10},)`; with strings `['apple', "zed's"]` it returns `({'a': "zed's"},)`. Cause: `src/bricksmith/quality/checks_rows.py:63` (PR branch) sorts by `repr(v)`, a text sort (`'10' < '2'`, `"` before `'`), while `checks_spark.py:41` uses `orderBy(*cols)` on the values and would pick `{'a': 2}` and `'apple'` (Spark side read, not run).

Consequence: #46 and #48 promise row/Spark parity on sample content and order; it fails whenever samples are truncated, for numbers and quoted strings alike. Audit every row-engine sample sort (grain, cardinality, comparison). Nulls-first must stay. Also correct #46's `## Outcome`, which says non-null values sort before nulls; the code and test put nulls first. Depends on #46 merging; serialize before #48, which edits the same files.
