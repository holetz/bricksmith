## Problem

`tests/unit/io/test_volumes.py::test_filesystem_client_and_symlink_escape` is the only test of
`FilesystemVolumeClient` (`grep FilesystemVolumeClient tests` → `test_volumes.py:132`). Since PR #8
its symlink step skips the whole test where `os.symlink` is not permitted
(`tests/unit/io/test_volumes.py:142-145`), so the assertions after it — `delete`, the second
`delete` raising `ArtifactNotFoundError`, and the `max_bytes` `LimitExceededError` check
(lines 149–153) — never run there.

Reproduction (Windows, no symlink privilege, 2026-10-15):
`uv run pytest tests/unit/io/test_volumes.py -rs` →
`SKIPPED [1] tests\unit\io\test_volumes.py:145: symlinks are not permitted on this system: [WinError 1314] ...`

Consequence: on such machines the delete and size-limit behaviour of the client is unverified by
the local gate, and CI does not currently run at all (spec 38), so no gate covers it. The
assertions pass when run without the symlink step, and a directory junction reproduces the escape
check without privilege. Proposal direction: split the symlink-escape check from the
delete/limit checks so only the former skips (or use a junction on Windows).

## Proposal

- The create/read/list/overwrite/delete/limit behaviour of `FilesystemVolumeClient` is asserted by tests that never need symlink privilege.
- Only the symlink-escape assertion skips where `os.symlink` is not permitted, and it skips on its own.
- `uv run pytest tests/unit/io/test_volumes.py -rs` on a machine without symlink privilege shows exactly one skip, for the escape test, and the delete and limit tests pass.

## Out of Scope

- Replacing the symlink with a directory junction on Windows: it adds a platform branch to a test and does not remove the need for the skip elsewhere; deferred as an optional follow-up.
- Changing `FilesystemVolumeClient` or CI: the client already behaves correctly and CI is spec 38's.

## Impact

### Standards this spec will write into docs/standards/

- none — a test-only change proves no new rule.

### Product code this spec expects to touch

- `tests/unit/io/test_volumes.py` — split `test_filesystem_client_and_symlink_escape`.

## Validation

- `uv run pytest tests/unit/io/test_volumes.py -rs` exits 0; with no symlink privilege only the escape test is reported skipped.
- `uv run ruff check && uv run ruff format --check && uv run pyright && uv run pytest` exits 0.

## Design

- Two tests: `test_filesystem_client_round_trip_delete_and_limit` holds the write/read/list/overwrite=False/delete/second-delete/max_bytes assertions with no symlink call; `test_filesystem_client_rejects_symlink_escape` creates the link, skips on `OSError`, and asserts `PathError` and that nothing was written outside.
- Durable rule: a platform-dependent precondition skips only the assertion that needs it, never unrelated behaviour in the same test.
- The assertions keep their current form and order within each test.

## Alternatives Considered

- A directory junction on Windows to keep the whole test: rejected, it adds a platform branch and still leaves the symlink dependency elsewhere.
- A `skipif` marker evaluated at collection: rejected, it needs a probe at import time for the same effect.

## Open Decisions

- none — the split is fully determined by the problem statement.

## Risks

- The new split could silently drop an assertion. Mitigation: move every assertion verbatim and compare the test diff.
- The escape test may now skip on a machine that previously ran it whole. ACCEPTED — that skip is the intended, narrower behaviour.
