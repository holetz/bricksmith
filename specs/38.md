## Problem

Every GitHub Actions run of .github/workflows/ci.yml on main fails in about 2 seconds with a billing annotation: the account's billing state refuses to start the jobs. CI has therefore never executed the gate, so no main commit has CI evidence, and merge policies that require green CI cannot be satisfied.

## Proposal

The repository owner resolves the account's Actions billing or spending-limit state, or decides on an alternative CI execution route. Then re-run CI on main and record the first real result. Code agents cannot act on account billing.

## Out of Scope

Workflow content changes, runner selection, CI authentication (spec #28) and generated CI surfaces (spec #29).

## Impact

GitHub account/repository settings only; no repository files.

## Validation

A CI run on main starts its jobs, gets past the setup steps and reports the gate result instead of a billing annotation. The run URL is recorded in this spec's Handoff.

## Open Decisions

needs-human: resolve GitHub Actions billing for the repository owner account, or choose an alternative CI execution route.
