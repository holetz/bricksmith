## Problem

Reproduced 2026-10-17 by the epic #47 correctness review on main (6f3ef40), range 77e04d9..6f3ef40.

`redact_text('password: | # note\n  s3cretvalue\nuser: bob')` → `password: <redacted> # note\n  s3cretvalue\nuser: bob`. Cause: `src/bricksmith/ops/redact.py:33`: `_BLOCK` allows only blanks between the `|`/`>` indicator (with optional chomping and indentation digit) and the newline, so a trailing `# comment` falls through to the bare-value path, which masks only `|`.

Consequence: valid YAML with a comment after a block-scalar indicator prints the secret lines in clear. Keep #41's linear-time bound.

## Proposal

- `redact_text` masks a block scalar whose `|` or `>` indicator is followed by a YAML comment (`password: | # note`): the secret lines are masked like any block scalar and nothing after the indicator survives.
- Plain block scalars, chomping and indentation indicators keep their current behaviour.
- #41's linear-time bound and #56's plural and suffix masking are preserved.

## Out of Scope

- The unquoted-value follow-up owned by #54, serialized after this spec.
- Folding a comment into the output: the comment is dropped with the masked value.

## Impact

### Standards this spec will write into docs/standards/

- none — a regression fix to an existing pattern; no standard changes.

### Product code this spec expects to touch

- `src/bricksmith/ops/redact.py` — the `_BLOCK` pattern
- `tests/unit/ops/test_ops.py` — regression tests

## Validation

- `uv run pytest tests/unit/ops/test_ops.py` passes, including `redact_text('password: | # note\n  s3cretvalue\nuser: bob')` equal to `password: <redacted>\nuser: bob`, and the same with `>-`, `|2` and `|+` indicators.
- A `#` glued to the indicator (`password: |#x`) is also treated as a comment, so the block lines never appear in output (redaction fails toward masking).
- The existing long-input timing tests (including a long run of blanks after the indicator) still pass.
- `uv run ruff check && uv run ruff format --check && uv run pyright` is clean.
## Design

- `_BLOCK` becomes `[|>](?:[1-9][+-]?|[+-][1-9]?)?[ \t]*(?:#[^\r\n]*)?(?:\r?\n|$)`: an optional comment after the blanks; a `#` without a blank is also taken as a comment because masking more is the safe failure.
- The match is attempted once per header via `.match` and scans forward once, so the cost is linear in the line length and #41's bound holds; no nested quantifiers are added.
- `_block_scalar_end` is unchanged: it starts at the end of the match, i.e. after the comment line's newline.
## Alternatives Considered

- Strip comments from the text before masking: rejected, it would alter unrelated output and add another full pass.
- Allow `#` without a blank: rejected, `|#x` is a plain scalar in YAML and the bare path already masks it.

## Open Decisions

- none — the accepted forms are settled in `## Design`.

## Risks

- Backtracking on a long blank run after the indicator: mitigated, one anchored attempt per header and a timing test in the same file.

## Outcome

The YAML block-scalar redaction now recognises a `#` comment after the block indicator (`|`, `>-`, `|2`, including a glued `|#x`), so the secret lines under it are masked. `_BLOCK` in `src/bricksmith/ops/redact.py` was widened beyond the blank-prefixed form first planned, because tests showed the glued case still leaked. Regression tests cover the indicators, the glued case and a long blank run within the time bound. Nothing was left out.
