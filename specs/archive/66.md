## Problem

Stability compares a period with a baseline through bins. If bins are recomputed per run, approximate quantiles move with physical file layout and compaction, labels stop matching, and PSI explodes without any real change in the data. Choosing bins by hand for every column of every table does not scale either. Columns with many exact zeros (amounts, balances, counters) hide their shape in one quantile bin.

## Proposal

- Extend `BinSpec` with an optional exact-zero bin for numeric columns (`zero: "separate"`), keeping existing serialized forms and fingerprints unchanged when the option is absent.
- Add `bricksmith.monitor.infer.infer_columns(types, distinct, rows, *, exclude, ...)` returning a bin configuration per column and a reason per skipped column, from a Spark-like type name per column and approximate distinct counts.
- Treat a stability binning as a versioned `Reference` (reuse, not a new type): frozen bins with fit counts, a fit window and a fingerprint; a new version is fitted only when the declared configuration changes or when explicitly requested.

## Out of Scope

- Supervised binning (target-aware merging) and information value — follow-up material.

## Impact

- `src/bricksmith/monitor/bins.py` (zero bin, pure and Spark assignment), `src/bricksmith/monitor/spark.py` (expression).
- `src/bricksmith/monitor/infer.py` — new.
- `tests/unit/monitor/test_infer_zero_bin.py` — new.

## Validation

- A reference fitted without `zero` serializes byte-for-byte as before (fingerprint unchanged).
- With `zero: "separate"`: zeros land in bin `zero`, quantile edges ignore zeros, `bin_ids()` order is `below, zero, bin_0.., above, null`; the Spark expression assigns the same ids (remote parity test).
- Inference: integer/decimal/double with distinct > `numeric_min_distinct` (default 20) → numeric quantile (10 bins, zero separate); numeric at or below it, string and boolean → categorical (`max_categories` 20); date, timestamp, binary, array, map, struct, variant, interval and null types → skipped with a reason; text with distinct > `max_text_distinct` (default 1000) → skipped `high_cardinality`; excluded columns (period, segments, weight, keys) → skipped `excluded`.

## Design

- `BinSpec.zero` is a bool; `to_dict` writes `"zero": true` only when set; `from_dict` defaults false.
- Assignment order: null → below/above (outside edges) → zero → interval.
- Quantile edges are fitted on non-zero, non-null values when `zero` is set; when every non-null value is zero, edges collapse to `[0, 0]` and all values go to `zero`.
- Inference never reads data itself: the stability engine passes types (`df.dtypes` or Python types of rows) and approximate distinct counts.

## Alternatives Considered

- Refit bins on every run. Rejected: unstable bins are the documented failure mode.
- A new binning type separate from `Reference`. Rejected: duplicate serialization and fingerprinting.

## Open Decisions

- none.

## Risks

- Approximate distinct counts near the threshold can flip a column's type between versions; the version records the decision, and a new version only happens on configuration change.

## Handoff

Keep BS-13 fixtures and fingerprints untouched; add regression asserts for the unchanged serialization.
