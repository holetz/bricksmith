## Problem

Found by the autopilot 2026-11-24 round 3 map (model scout), reproduced on main 73c8775 with the data of `test_few_expected_events_are_insufficient_volume_whatever_the_observed_count` (`tests/unit/monitor/model/test_model_credit.py:149`), then `replay_alerts(..., config=config)`:

```
grade_oe / grade_jeffreys_p / grade_binomial_p: insufficient_volume -> red
alerts check []   alerts replay: 3 x ('open','critical') on grade=D
```

During a run, `src/bricksmith/monitor/model/engine.py:840-842` gates a grade result to `insufficient_volume` when its expected events fall below `credit_options.min_expected_events`, and `engine.py:830` skips `min_rows` for results that carry expected events. `relight` (`src/bricksmith/monitor/model/alerts.py:63-104`), used by `replay_alerts` with a config, does neither: it applies `min_rows` to every non-volume metric (`alerts.py:71`) and colors the row by its limits alone; `judge`/`classify` honor a stored reason only for `no_data`/`no_baseline`, so the stored "expected events ... < min" reason does not keep the gate.

Consequence: `model-monitoring alerts --config` (`cli.py:55`) and `replay_alerts` turn low-volume calibration results red and open critical alerts that the run suppressed, contradicting `docs/how-to/model-monitoring.md:141`; conversely a grade with few rows but enough expected events is gated by `min_rows` on replay but not in the run.

Proposal: make relight apply the same volume rules as the run (expected-events gate and the `min_rows` exemption for rows with expected events), reading the stored expected events or the stored gate reason; add a regression test asserting replay with config keeps `insufficient_volume` and opens no alert for the case above.

## Proposal

- `relight` (replay with a config) applies the run's volume rules: results that carry expected events (`grade_oe`, `grade_jeffreys_p`, `grade_binomial_p`, `grade_binomial_adjusted_p`, `early_oe`) are exempt from `min_rows`, and a stored `expected events X < min Y` gate stays `insufficient_volume` while X is below the declaration's current `min_expected_events`.
- A regression test replays the case of `test_few_expected_events_are_insufficient_volume_whatever_the_observed_count` with the config and asserts `insufficient_volume` and no alert; a second test pins the `min_rows` exemption for a grade with few rows but enough expected events.
- `docs/how-to/model-monitoring.md` states that replay keeps the gate.

## Out of Scope

- Storing expected events as a results column (a table-contract change): the stored reason already carries the number.
- Re-gating with a raised `min_expected_events`: a row that passed the gate stores no expected events, so a raise needs a new run.
- Report replay with the persistence policy (spec 114).

- `uv run ruff check`, `uv run ruff format --check` and `uv run pyright` stay clean.

## Design

- Decision: read the stored reason, not a new column. `_result` writes `expected events {x:.4g} < min {y:g}`; relight parses `x` back (a shared prefix/regex lives next to the format in `engine.py`) and keeps `Light(INSUFFICIENT_VOLUME, reason)` when `x` is below the declaration's current `min_expected_events`; otherwise the row is colored by its limits as before. Parsing keeps a lowered threshold effective on replay.
- Decision: the `min_rows` exemption is keyed on the metric name set `EXPECTED_METRICS`, because stored rows do not say whether the run had expected events; the set is the metrics `credit.py` emits with `expected=`.
- Binding contracts: `docs/how-to/model-monitoring.md` (gate section) is the documented behavior; the code is brought in line. Free-first: pure unit tests, no remote proof.

### Assumptions

- Rows stored by a run that predates this fix carry the same reason text (the format is unchanged) — Design decision above depends on it.

## Alternatives Considered

- New `expected_events` results column: rejected, table-contract change for a value already in the reason.
- Keep any stored `insufficient_volume` regardless of config: rejected, a lowered `min_expected_events` would not take effect on replay.

## Open Decisions

- none — evidence and the epic's Proposal decide the shape.

## Risks

- The reason text is parsed: a format change in `_result` would silently disable the gate. Mitigated by one shared format constant and the regression test.
- A raised `min_expected_events` is not applied on replay: ACCEPTED and documented.
