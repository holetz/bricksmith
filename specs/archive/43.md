## Problem

A freshness threshold too large for a float escapes the documented `QualityError` contract.

Reproduction (2026-10-16): `Check.freshness("ts", max_age_seconds=10**400)` raises
`OverflowError: int too large to convert to float` at `src/bricksmith/quality/checks.py:30`
(`math.isfinite`); `Check.from_dict(...)` with the same value fails the same way at `:39`
because `:40` only catches `ValueError`; `load_checks('[{"kind":"freshness",…,
"max_age_seconds": <400 digits>}]')` raises `OverflowError` too. Before PR #12 the value was accepted.

Consequence: callers that handle `QualityError` for invalid configuration crash on a malformed
check file instead of reporting it.

## Proposal

Treat an integer too large for a float as an invalid threshold: `_finite_non_negative` and `_number` catch `OverflowError` and the callers raise `QualityError`, so direct construction, `Check.from_dict` and `load_checks` all report invalid configuration with the documented exception.

## Out of Scope

Supporting arbitrarily large thresholds, new defaults, and changes to other checks.

## Impact

src/bricksmith/quality/checks.py; tests/unit/quality/test_checks.py. No standards declared.

## Validation

`uv run pytest tests/unit/quality -q` passes with new cases for `10**400` via `Check.freshness`, `Check.from_dict` and `load_checks`; the full gate (ruff check, ruff format --check, pyright, pytest) exits 0.

## Design

`float(10**400)` and `math.isfinite(10**400)` raise `OverflowError`. Catch it at both sites and map to the existing `QualityError` messages; no other behavior changes. Policy: epic 5 `## Design` (resumed 2026-10-15; billing amendment).

## Alternatives Considered

Clamp huge values to infinity: rejected, as nonfinite thresholds are already rejected.

## Open Decisions

- none — the fix follows the existing contract that invalid thresholds raise QualityError.

## Risks

Low: only inputs that previously crashed with OverflowError change behavior.
