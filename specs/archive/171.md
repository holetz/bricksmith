## Problem

Found in #166 (PR #115) by the round-2 reviewer on 2026-11-26 (main 5a8ed5b):

```
for c in ['firewallpass=hunter2','simpass=1234','callpass=hunter2']: print(redact_text(c))
firewallpass=hunter2
simpass=1234
callpass=hunter2
```

`src/bricksmith/ops/redact.py:38` applies the 12 exempt words as lookbehinds (`(?<!all)`, `(?<!im)`...), so any qualifier ending in them (`firewall`, `call`, `sim`) is exempt too — contradicting the fail-closed comment at `:22-23`. Consequence: credential values leak. Exempt only when the whole qualifier is in the denylist (`allpass`, `impass`, ...), keeping linear time (#41) and the `lowpass`/`highpass`/`bypass` cases unmasked.

## Proposal

- Exempt a `<qualifier>pass` key only when the whole letter run before `pass` is one denylisted word (`lowpass`, `bypass`, `compass`...); anchor each fixed-width lookbehind at the text start or a non-letter (`(?<!^w)(?<![^a-z]w)`).
- Add the reviewer's reproduction plus a table of adjacent adversarial variants as regression tests.

## Out of Scope

- Growing or changing the 12-word denylist.

## Design

- Fixed-width lookbehinds only, so the match stays linear (#41).
- Epic 173 decision (2026-11-26): close the class with the reproduction plus adjacent variants; no over-redaction of ordinary text.
- Uppercase `LOWPASS` was already masked on main (pre-existing, fail closed); unchanged.

## Alternatives Considered

- Variable-width lookbehind or lookahead scan of the run: not supported by `re` / risks quadratic time.
