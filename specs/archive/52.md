## Problem

Secret values still leak for several spellings, reproduced 2026-10-17 by the epic #47 correctness review on PR #21 (spec #42); items 2–4 also leak identically on main (cbe316f).

1. Escaped quote inside an escaped-quoted value: `{\"password\": \"a\\\" b c\"}` → `{\"password\": \"<redacted>\" b c\"}` (` b c` leaks). Cause: PR `redact.py:67` skips backslash escapes when the opening quote is `\"`.
2. Nested YAML map: `credentials:\n  password: s3cretvalue` → `credentials:\n  <redacted> s3cretvalue`. Cause: separator `\s*` at PR `redact.py:26` crosses the newline, the bare value at `:34`/`:109` swallows the child key, and the child match is skipped at `:96`.
3. Block scalar with indentation indicator: `password: |2\n  s3cretvalue` and `password: >2-\n  s3cretvalue` leave the value visible. Cause: PR `redact.py:32` does not accept YAML's indentation digit.
4. Spaced JDBC parameter: `jdbc:x://h;user=a; password=abc def;db=1` leaks `def`. Cause: PR `redact.py:105` reads to the next `;` only when the key directly follows `;`.

Consequence: secrets reach logs and reports for real config spellings. Depends on the redaction rewrite in #42 landing (build on its single pass); keep #41's linear-time bound.

## Proposal

- An escaped-quoted value containing an escaped quote (`{\"password\": \"a\\\" b c\"}`) is masked whole.
- A nested YAML child key under a sensitive parent (`credentials:\n  password: s3cretvalue`) keeps the parent key and masks the child value.
- Block scalars with an indentation indicator (`|2`, `>2-`, `|-1`) are masked like plain block scalars.
- A JDBC parameter with spaces after the semicolon (`; password=abc def;db=1`) is masked up to the next `;`.

## Out of Scope

- Reworking the redaction architecture: the single left-to-right pass from #42 stays.
- New keyword families or other value spellings not reproduced in the #47 review.

## Design

- Escaped-quote mode: scan a run of backslashes; when a quote follows, the run is the closer only if its length is exactly 1, otherwise it is an escaped quote or escaped backslash and is consumed whole. Each character is visited once, so the bound stays linear.
- `_SEP` uses `[ \t]*` around the operator so it never crosses a newline; a header ending a line has no bare value, so the child line matches as its own header in the same pass.
- `_BLOCK` accepts the YAML header `[|>]` followed by an optional indentation digit 1-9 and chomping `+`/`-` in either order.
- The semicolon rule looks back past spaces and tabs before the key to find `;`.
- Durable rule: every masking rule consumes input left to right once; no rule rescans or backtracks over a prior value.

## Alternatives Considered

- A second pass for nested YAML: rejected, it breaks the single-pass guarantee from #42.
- A full YAML or JDBC parser: rejected, redaction must work on arbitrary log text.

## Risks

- A tighter separator could stop masking a value placed on the next line (`password:\n  value`): existing tests cover it, and the block-scalar path is unchanged.
- Backslash-run handling could introduce quadratic behaviour: the run is consumed in one step and the linear-time test guards it.
