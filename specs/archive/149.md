## Problem

Periods are whatever text values the table holds, sorted as text (docs/how-to/stability.md:48). If the
expected latest period never arrives, the check simply judges the previous latest period again and passes; a gap
in the middle of history is invisible, and `previous`/`rolling` baselines silently compare across the gap.
Freshness exists only as a separate quality check (`quality/checks.py:125`), not in the stability results or
dashboards.

## Proposal

- `cadence: day | week | month | none` plus optional `expected_by` (e.g. 5 days after the period end) and
  `as_of` from the run context.
- Table-level results `period_missing` (an expected period has no rows) and `period_late` (the latest expected
  period is missing after `expected_by`), judged and alerted like other metrics and counted by the gate.
- Baselines skip over gaps explicitly and record `baseline_gap` on the result.
- `settle_periods` / `settle_days`: the most recent periods still receiving late data are judged and shown but
  kept out of baselines, trend histories and the gate until they settle (the equivalent of Elementary's
  `detection_delay`).
## Out of Scope

- Row-level timestamps freshness (the quality freshness check stays the tool for it).

## Validation

- A monthly table missing its latest month is red on `period_late` after `expected_by`, and a gap month
  appears as `period_missing`.

## Design

- **Cadence is a calendar over `period_date`.** `cadence: day|week|month` steps the period start date by 1 day, 7 days or one calendar month; `none` (default) keeps today's behavior and every serialized form unchanged. Missing periods are written in the text format of the latest data period (`YYYY-MM-DD`, `YYYY-MM`, `YYYYMMDD`, `YYYYMM`). A period that is not a date makes the check refuse (`MonitorError`), as the Risks section requires.
- **`expected_by` is whole days after the period end** (day: the date; week: start + 6; month: month end). A period is overdue when `as_of` is strictly after its deadline. `as_of` is a `check(..., as_of=)` input (an ISO date), default today in UTC; the CLI exposes `--as-of`. The task hook uses the default.
- **Table-level results.** `period_missing` is judged for every calendar period between the first data period and the expected latest one that has no rows (value 1, red); `period_late` is judged on the expected latest period (value 1, red) when it has no rows. Both are ordinary results (segment `""`, column `""`), with default limits in `CADENCE_LIMITS` (green 0, red 1, higher) so declarations without cadence keep their serialized limits. Rows are emitted every run for the window of expected periods (bounded by `max_periods`); a stored non-green row whose period has since arrived is rewritten green, so no stale red survives.
- **Gate and alerts.** Cadence results enter the alert replay with the other results, and the check's latest period becomes the expected latest period when that one is late, so the gate counts `period_late`.
- **Baseline gaps.** Baselines already pick among periods that exist; with a cadence the result records `baseline_gap`, the number of calendar periods absent between the earliest baseline period and the judged period (0 without cadence).
- **Settling.** The most recent `settle_periods` periods of the data, plus periods whose end is within `settle_days` of `as_of`, are `settling`: judged and shown (`settling` true on their results) but excluded as baseline periods, from trend histories and from gate counts. `settle_days` needs a cadence (it needs period ends).
- **Result schema.** `baseline_gap` INT and `settling` BOOLEAN are appended to the results table; stability tables already evolve (`evolution`), so existing tables gain the columns.

### Assumptions

- The run context carries no date, so `as_of` defaults to the wall clock (Impact; Validation fixes it explicitly).

## Alternatives Considered

- Reusing the quality freshness check: rejected, it reads row timestamps and is not part of stability results or dashboards.
- Writing a result row for every calendar period, present or not: rejected as noise; only missing, late and previously non-green rows are written.

- Period text formats vary; reuse `period_date` and refuse `cadence` when periods are not dates.
