## Problem

Found by a supplementary corporate run (2026-11-24):

- `scripts/features_benchmark.py` stops with `ConfigError: cannot read dotenv file …/.env` when no `.env` exists, even with every setting in the process environment. The remote test harness treats `.env` as optional, and the benchmark should too, so a CI runner or a borrowed workstation can run it.
- One benchmark run at size M (50,000 entities × 36 closings × 10 columns) takes over an hour on an 8-vCPU single node, and the script prints nothing until the end and has no time budget. The script should print per-engine and per-family progress and accept a time budget that stops cleanly with partial, labelled results.
- Spec 91 adds the JVM engine to the benchmark. The script must accept the engine list, including `jvm`, and a single-closing (`as_of`) mode, since the corporate measurements show engine rankings differ between all-closings and one-closing runs.

Files: `scripts/features_benchmark.py`, `src/bricksmith/features/benchmark.py`, `tests/unit/features/test_benchmark*.py`.

## Proposal

`scripts/features_benchmark.py` becomes runnable from a bare process environment and observable while it runs:

- The `.env` file is optional, as in the remote test harness: when it is absent the context is selected from the process environment alone.
- `run_benchmark` reports progress (one line per measurement, on stderr) and accepts a time budget. The budget is checked between measurements, never mid-measurement; on expiry the run stops cleanly, returns the timings gathered so far and the report says it is partial and lists what was not run.
- The engine list is validated against the engines the build knows (`reference` plus `bricksmith.features.engines.ENGINES`), so an engine added later (spec 91's `jvm`) is accepted without a script change; an engine this build does not have is refused with a message naming the known ones.
- A single-closing mode (`--single-closing`) times each Spark engine and the reference at one closing (`as_of` = the last closing of the synthetic table) instead of every closing.

## Out of Scope

- The JVM engine itself, its build and delivery (spec 91).
- Changing the engines' defaults, or recording new benchmark results in the evidence page.
- Running the benchmark at size M on any workspace; the proof uses small synthetic sizes on the free context.

## Design

- 2026-11-24 — **Optional `.env`.** `load_dotenv` is called only when `ROOT / ".env"` is a file; otherwise an empty mapping goes to `resolve_context`, which still layers arguments, process environment and defaults. A missing context is then reported by `resolve_context`, not by a file-read error.
- 2026-11-24 — **Budget.** `Budget(seconds, clock=time.monotonic)` is a small object passed to `run_benchmark`; it is checked before each measurement (and before each size's data generation). It records the `(size, family, engine)` cells it skipped, so the script writes a `partial` note naming how many cells were not run. A measurement already started finishes: a clean stop beats an interrupted one, at the cost of overshooting by up to one measurement. Warm-up runs count against the budget like any other.
- 2026-11-24 — **Progress.** `run_benchmark(..., progress=callable)` receives one text line per event (source materialization, each timing, the stop); the script passes a writer to stderr so stdout stays the report only. Default is silent so the library call is unchanged.
- 2026-11-24 — **Engines.** Validation is dynamic: `{reference, *engines.ENGINES}`. An unknown name refuses with `FeatureError` listing the known ones. No `jvm` literal is added here; spec 91 registers it in `ENGINES`.
- 2026-11-24 — **Single closing.** `as_of` is the last closing of the table (the only value that never meets rows after the cutoff). It is passed to `compute_features` and `compute_rows`. The report note states the mode; it is a separate run, not a column, so all-closings and one-closing reports are compared by the reader.

## Alternatives Considered

- Return a result object from `run_benchmark` carrying `partial`: rejected, it breaks every caller of the `list[Timing]` return; a `Budget` the caller owns reports the same fact.
- Interrupt a running measurement at the deadline: rejected, a half-timed cell is not a result and cancelling a remote job is engine-specific.
- A literal `jvm` in the engine list now: rejected, it would accept a name the build cannot run.

## Open Decisions

- none — the epic's design bullets of 2026-11-24 and the problem statement settle every choice above.

## Risks

- The budget overshoots by up to one measurement, which at size M can be long. Mitigation: documented; progress lines show where the run is.
- The single-closing run on the reference engine still pays the whole-table computation if `compute_rows` does not prune; the measured number then says so rather than hiding it.

## Outcome

The feature benchmark (`scripts/features_benchmark.py`, `bricksmith.features.benchmark`) now runs from the process environment alone, reports progress and can be bounded in time.

**Shipped**
- The `.env` file is optional: the script loads it only when it exists, so a CI runner or a borrowed workstation selects the context from `BRICKSMITH_*` variables, as the remote tests do.
- One progress line per event goes to stderr (source, each measurement start and result, budget skips); the markdown report stays on stdout.
- `--budget SECONDS` (`Budget`) is checked between measurements and between sizes, never inside one. The report keeps what ran, is labelled partial and lists the measurements not run; a started measurement finishes, so the run can overshoot by up to one.
- `--single-closing` times the last closing of each size (`Size.last_closing` as `as_of`) instead of every closing; the report notes the mode.
- `--engines` validation is dynamic over `reference` plus `engines.ENGINES`, so a new engine (spec 91's `jvm`) needs no script change.
- `docs/how-to/features.md` documents the environment, budget, single-closing and engine options. Tests cover the budget, single-closing, progress and the no-`.env` run (the latter fails on the base tree).

**Proof**: unit tests, ruff, pyright and the full pytest are green. The free-context remote proof ran with no `.env` in the worktree: single-closing spark 20x6x2, and a 3 s budget run labelled partial, both exit 0.

**Left out**: no change to the measured engines or the report table shape; no resume of a partial run; rankings between all-closings and single-closing modes are documented as possibly different, not reconciled.

**Next reader**: the budget is wall-clock and coarse by design (one measurement of overshoot). No release obligation applied; no flow-sweep candidate found.
