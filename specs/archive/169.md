## Problem

Found in #167 (PR #117) by the round-2 reviewer on 2026-11-26 (main 5a8ed5b):

```
python3 -I -c "import sys; sys.path.insert(0,'src'); from bricksmith.ops.redact import redact_text as r; s='token=[\n'*5+'password: [\n  \"hunter2\"\n]\n'+'x'*20000; o=r(s); print(repr(o[:140]), 'hunter2' in o)"
'token=<redacted>\n…\npassword: <redacted>\n  "hunter2"\n]\nxxx' True
```

With one prefix line instead of five, `hunter2` is masked. `src/bricksmith/ops/redact.py:177-182,189`: each unclosed-bracket scan costs about `len(text)-start`, so a few early unclosed brackets spend the global 4n+4096 budget and every later bracket falls back to `_first_line_end`. Consequence: an attacker-shaped or simply messy log re-exposes the secret lists #167 meant to mask. The fix must stay linear (#41) without a shared budget that early input can exhaust (e.g. a single forward pass that resolves all bracket ends).

## Proposal

- Replace the shared rescan budget in `src/bricksmith/ops/redact.py` with a single forward pass per unresolved start that resolves the matching `]` of every bracket it visits, so an early unclosed bracket never changes how a later list is masked.
- Add the reviewer's reproduction and a table of adjacent adversarial variants as regression tests, plus an exact-output no-over-redaction test and keep the #41 timed bound.

## Out of Scope

## Design

- One stack-based pass from a bracket start resolves every bracket opened in the unquoted state during the pass; results are cached by start index. A cached unclosed result ends the pass (all enclosing brackets are unclosed too); a cached match jumps past it.
- Brackets first seen inside a quoted region of an earlier pass start their own pass. Only such rescans of already-scanned text draw from a 4n+4096 backstop budget; fresh text and ordinary unclosed brackets cost nothing from it, so early input cannot exhaust it.
- Epic 173 decisions: every fix closes the class, with the reproduction plus adjacent adversarial variants, a no-over-redaction test, existing tests green, the #41 timed bound, no new suppressions, pytest basetemp outside the worktree.

## Alternatives Considered

- Per-scan constant window: rejected, quadratic-ish with a large constant.
- Raise the shared budget: rejected, still exhaustible by early input.

## Open Decisions

## Risks

- Quoted-state rescans keep a backstop budget; an input built only of quote-mismatched brackets can still exhaust it and fall back to first-line masking.
