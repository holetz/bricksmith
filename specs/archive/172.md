## Problem

Gap left by #165 (PR #116), reproduced by the round-2 reviewer on 2026-11-26 (main 5a8ed5b; base 48f4a94 identical):

```
redact_text('postgres://bob:p/ss@word@db.example.com')  -> 'postgres://bob:<redacted>@word@db.example.com'
```

Same with `p?ss@word`. `src/bricksmith/ops/redact.py:235-236`: `path` is the first `/?#` anywhere in `rest`, including inside the password, so the real separator before `db.example.com` is popped as an "address tail" and `word` leaks. Consequence: part of the password is logged. Locate the path start only after the last plausible userinfo `@` (or prefer the rightmost `@` whose suffix is a valid host[:port] followed by end, `/`, `?` or `#`), keeping #60/#165 cases and linear time.

## Proposal

- Decide whether the last `@` is a path address by looking only at the span between the previous `@` and it: it is one only when a `/`, `?` or `#` separates a non-empty host from it. A `/` or `?` inside the password (before the first `@`) no longer counts as the path start.
- Add the reviewer's reproduction plus a table of adjacent adversarial variants as regression tests.

## Out of Scope

- Changing the `host:port` branch (a password starting with 1-5 digits then `/`), which stays ambiguous and fails as before.

## Design

- `_after_host` searches `/?#` only inside `(previous @, last @)`, so total work stays linear across pops (#41).
- Epic 173 decision (2026-11-26): close the class with the reproduction plus adjacent variants; no over-redaction of ordinary text.

## Alternatives Considered

- Locating the path start after the last plausible userinfo `@` by regex: needs lookahead over the whole tail, risking quadratic time.

## Risks

- A benign address deep in a path after a second address may stay masked as before; this errs toward not leaking.

## Outcome

The last `@` is now treated as a path address only when a `/`, `?` or `#` separates a non-empty host from it, searched between the previous `@` and it. A bare-host URL whose password holds both `/` or `?` and `@` is masked whole (`postgres://bob:p/ss@word@db.example.com` → `postgres://bob:<redacted>@db.example.com`). Regression table of adjacent variants and a timed 4k/64k test were added; reviewed, no docs to distil. Left out: the `host:port` ambiguity for passwords starting with digits then `/`.
