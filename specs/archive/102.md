## Problem

- The example's `model_monitoring` block (`examples/model_flow/catalogs/demo/flow/model.py:227-239`) has no `credit` key although the model has grades A–D (`models/attrition.toml` bands); `docs/how-to/model-flow.md:157-161` never mentions calibration per rating. Jeffreys and binomial tests, the volume gate and the grade-order check never run in the example.
- `tests/unit/mlops/test_model_flow_example.py:208-222` only calls `parse_config` and checks names; it never runs `engine.check` with a `MemoryStore` (the offline path used in `tests/remote/test_model_monitoring.py:13`). With `label_lag: 3` and six live periods, every label-based metric could be `data_period_unavailable` with no test failing.

Consequence: the end-to-end example does not show model monitoring producing stability, mature-label performance or calibration results.

Proposal: declare `credit` in the example and document it in the model-flow guide; add an offline synthetic unit test that runs the example's declaration through the engine and asserts that score/feature stability, KS/AUC/Gini at the matured periods and per-grade calibration rows have values.

## Proposal

- The example's `model_monitoring` declaration carries a `credit` block (probability horizon, grades A–D best first), so grade calibration (O/E, Jeffreys, binomial, volume gate) and grade order run in the example.
- `docs/how-to/model-flow.md` states that the example monitors calibration per rating and names the credit block it declares.
- An offline synthetic unit test runs the example's own declaration through `engine.check` with a `MemoryStore` and asserts that score and feature stability, KS/AUC/Gini at matured periods and per-grade calibration rows have values.

## Out of Scope

- Early-warning horizons and the exclusion mix: the example has no per-horizon label columns and the exclusion column is not in the scores table. Deferred to spec 103.
- Estimating performance before labels mature: needs evidence and goes to the human epic.
- Any corporate-workspace execution: Free-first, none this round.

## Design

- Rule: the example declares everything the guide claims; the proof runs the declaration itself (read from the task's metadata), never a copy, so the declaration and the proof cannot drift.
- The probability horizon is 3 periods, the example label's horizon (`models/attrition.toml` `[label] horizon = 3`); grades are the toml bands A–D, best first.
- The test builds synthetic rows shaped like the `attrition_scores` output (closing date, score, label, grade, sample, three features) and respects `label_lag: 3`: the last three live periods have no mature label, so label-based metrics there are `data_period_unavailable` and earlier ones carry values. Rows are independent synthetic data (decision 0010).
- Alternative weighed: asserting only that `parse_config` accepts `credit` (the current weakness); rejected, it proves no result row.
- Binding: `monitor/model/config.py` credit block keys; `tests/remote/test_model_monitoring.py` offline `MemoryStore` pattern. No Spark engine involved, so the Scala feature engine question does not arise.

## Alternatives Considered

- Putting the proof in `tests/remote`: rejected, the offline path is free, fast and runs in the gate.
- Adding early-warning now: rejected, needs data columns that belong to 103.

## Open Decisions

- none — the horizon and grades follow the example's own label and bands.

## Risks

- A grade with few expected events is gated as `insufficient_volume`, so a test asserting values must size the synthetic rows above `min_expected_events`; mitigated by sizing the fixture per grade.
- Declaring `credit` changes the example's monitoring fingerprint; ACCEPTED — the example is a demo with no stored history.
