## Problem

A supplementary corporate run (2026-11-24) exercised the model lifecycle on Unity Catalog for the first time. It got past training, artifact upload, version registration, alias `champion`, alias-bound predict/evaluate, pinned reload and promotion. It found:

- **F1. Version resolution fails on Unity Catalog** (severity high). `ModelStore.versions` reads `item.tags` from `search_model_versions`. On Unity Catalog those results carry no tags (`tags` is a method that raises), so every alias and version resolution fails with `TypeError: 'method' object is not iterable`. Fix: read tags per version (`get_model_version`) when search omits them.
- **F2. The alias history overflows the tag limit** (severity high). It is kept as one JSON value in a registered-model tag, and Unity Catalog caps tag values at 256 characters, so the second history entry (a rollback) already fails with `INVALID_PARAMETER_VALUE … exceeds the maximum length of 256 characters`. Per-version review events (`MAX_EVENTS = 8`) are at the same risk. The history needs a representation within Unity Catalog limits: one bounded tag per event, a run artifact, or a Delta table. That choice is this spec's design decision.
- **F3. A failing test leaves its experiment behind.** When a remote model test fails inside its `finally`, a raising `delete_model` skips `delete_experiment`, and the experiment stays on the workspace. Cleanup steps must be independent.
- **F4. The remote model test was never correct.** `tests/remote/test_models.py` runs the predict task with `upstream=False` although nothing built the prediction dataset (`TABLE_OR_VIEW_NOT_FOUND`). It also expects a positive rate of 0.6 copied from the unit fixture, while the example's eligible rows give 2/5 = 0.4. The test had never got this far on any environment.

Related: spec 88 (artifact listing empty on the free tier), spec 2 (artifact download for registration). Corporate evidence shows that nested artifacts list and download on a corporate workspace, so 88 is free-tier specific.

Files: `src/bricksmith/mlops/store.py`, `tests/unit/mlops/test_models.py`, `tests/remote/test_models.py`.

## Proposal

Make `ModelStore` work on Unity Catalog end to end, and make its remote test correct:

1. **F1, version tags.** `ModelStore.versions` uses the tags of a search result only when they are a mapping;
   otherwise (Unity Catalog, where `tags` on a search result is a method that raises) it reads each version with
   `get_model_version`.
2. **F2, lifecycle metadata within Unity Catalog tag limits** (tag value at most 256 characters, at most 50 tags
   per object):
   - **Review events** (per version): one tag per event, `bricksmith_event_<seq>` (zero-padded sequence), each
     value compact ASCII JSON of at most 256 characters. Free-text fields (`reason`, then `reviewer`) are shortened
     with a `...` marker when the event would not fit. Only the newest `MAX_EVENTS` (8) are kept; older event tags
     are deleted. A legacy `bricksmith_events` list tag is still read (oldest first) so versions written before this
     change keep their history.
   - **Alias history** (per registered model): one tag per alias, `bricksmith_history_<alias>`, holding only the
     transitions rollback needs, compact `[[from,to],...]` pairs, newest kept, trimmed from the oldest so the value
     fits 256 characters and holds at most `MAX_EVENTS` entries. The legacy list-of-objects value is still read.
     Who/why/when of each change stays in the target version's review events, which the model card renders.
3. **F3, independent cleanup.** The remote model test deletes the experiment even when deleting the model raises.
4. **F4, correct remote test.** The remote test builds the prediction dataset before predict/evaluate and expects
   the example's real positive rate.

## Design

- Events are keyed `bricksmith_event_%06d`; the next sequence is one more than the highest present (legacy list
  entries do not consume sequence numbers). After writing, event tags beyond the newest `MAX_EVENTS` are deleted
  with `delete_model_version_tag`. `events()` returns legacy entries then keyed entries in sequence order, newest
  `MAX_EVENTS` overall.
- Fitting an event: `json.dumps(..., sort_keys=True, separators=(",", ":"))` (ASCII, so characters equal bytes);
  while longer than 256, shorten `reason`, then `reviewer`, keeping a `...` suffix; if structural fields alone
  exceed the limit, raise `ModelError` rather than write a truncated structure.
- History: `record_history` stores `[from, to]` pairs only; `history()` returns `[{"from": a, "to": b}, ...]`,
  accepting legacy dict entries. `plan_rollback` already reads only `from`/`to`.
- Tag budget per version: model, state, caller tags and at most 8 events; per registered model: model and one
  history tag per alias. Both stay well under 50.
- `versions()`: `tags = item.tags if isinstance(item.tags, Mapping) else self.tags(name, version)`; a non-callable
  missing attribute also falls back.

### Assumptions

- Unity Catalog counts tag values in characters; ASCII-only JSON makes characters and bytes equal (Design).
- The 50-tags-per-object limit applies to model versions and registered models (Databricks migration guide);
  the budget above holds either way (Design, Validation).

## Alternatives Considered

| Shape | Cost | Buys | Forecloses |
| --- | --- | --- | --- |
| **Bounded tags (chosen)** | small change in `store.py` | works on Unity Catalog and workspace registry with no new storage | full-text reasons beyond ~150 characters are shortened |
| Run artifact per alias history | needs a run to own history; artifact listing is broken on the free tier (spec 88) | unbounded text | free-tier testing |
| Delta table of lifecycle events | a table, a schema decision and Spark in the store | unbounded, queryable | the store's Spark-free design |

- The remote test may still stop on the free tier at registration (spec 88); recorded as Unsupported, not hidden.
