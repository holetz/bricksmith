## Problem

The human asked (2026-11-23, autopilot) for a consolidated model development (MLOps) flow and a complete model monitoring flow in bricksmith, working with the existing data-stability core and delivering no less than a mature private reference implementation (behaviours only; see decision 0010): a feature store based on closings rather than approximate event time; feature engineering with a rich windowed aggregate catalog, improved over an existing positional-array UDF and benchmarked with an Arrow engine; feature selection; explicit population, ABT, prediction and modelling stages; technical documentation; and monitoring with discrimination, calibration, stability, maturation, traffic lights, trend, persistence, human alert actions, reports and governance views.

- 2026-11-23 — **Feature store design (76).** Plain Unity Catalog Delta tables written by ordinary tasks, primary key = entity keys + closing date (DATE), exact equality join on closing; rows stamped at the closing the source became available (availability lag). Databricks Feature Engineering is an optional, lazily imported adapter, never a requirement: a DATE key in a feature table must be TIMESERIES (as-of join) or STRING for exact match (docs.databricks.com feature-store/time-series, 2026-09-11); Feature Views are public preview and refuse date entity columns (2026-11-11 docs), so they are not a dependency. One training-set builder serves training and scoring; only the spine differs.
- 2026-11-23 — **Feature engineering engines (77).** Native Spark is the default candidate (expressions generated from a declarative spec, one WindowSpec per entity ordering, closed-form OLS); a numpy reference is the oracle; an Arrow engine (`applyInArrow`/`mapInArrow` on DBR 18+, else `applyInPandas`) is measured, not assumed (Databricks reports Arrow UDFs ~10% faster and ~40% leaner than pandas UDFs, 2026-05-20). The default engine per aggregate family is chosen from the recorded benchmark. pyarrow goes in an extra, never the root import. Known statistical bugs of positional-array approaches (non-absolute sum of differences, stale skew/kurtosis term, R² as SSE/SST, tercile division by zero, percentile overflow) must be covered by golden tests.
- 2026-11-23 — **Selection and docs (78, 80).** Thresholds are configuration, not truth; PSI may use sample-size-aware critical values; supervised transforms (WoE, supervised bins) are fitted on training and never stored in feature tables. Documentation is deterministic from persisted artifacts and a run id; regulator-neutral section names; no "compliant" branding (SR 11-7 was replaced by SR 26-2 on 2026-04-17).
- 2026-11-23 — **Monitoring (81, 70–73, 82, 83).** bricksmith computes and stores its own monitoring tables; Databricks data profiling is not a dependency (its time-series/inference profiles cover only the last 30 days, too short for 12-period maturation). Feature drift (CSI) shares bins with data stability. Calibration per grade uses Jeffreys and binomial tests with an expected-events volume gate (ECB validation-reporting instructions); a correlation-adjusted binomial is optional (EBA staff paper 24, 2026-04-29). Performance estimation before labels mature is out of scope this epic.
