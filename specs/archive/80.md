## Problem

Evaluation stops at a single discrimination metric and technical documentation is hand-written HTML with no link to the run, data windows or feature set, so it drifts from the model it describes. `mlops/meta.py:185` renders a short model card only.

## Proposal

- An evaluation step per sample (train, test, out-of-time) and per closing: KS, AUC, Gini, score distribution, PSI of the score and CSI of each selected feature between samples, calibration (observed/expected per grade, Brier), grade/band ordering (inversions), logged to MLflow and persisted as tables.
- A documentation generator that renders, deterministically from persisted artifacts and a run identifier, a technical model document (Markdown and self-contained HTML): purpose and use, population and exclusion counts by sample, target definition and maturity, sample windows, feature store lookups and versions, the selection ledger, binning/WoE tables, model specification (coefficients or score points, or importance for tree models), evaluation tables per sample, calibration, stability, limitations, and an inherent-risk and materiality section. Section names are regulator-neutral; no "compliant" branding; numbers are never free text.
- The document is logged as an MLflow artifact and its location tagged on the registered model version; regenerating from the same run yields the same bytes (except an explicit generated-at field).

## Out of Scope

- LLM-written narrative inside the generated document.

## Design

- 2026-11-23 — **Binding context.** Epic 85 `## Design` bullets of 2026-11-23 (private-source rule; selection and docs decisions; monitoring decisions) bind this spec and are not re-derived here: thresholds are configuration, supervised transforms are fitted on training, documentation is deterministic from persisted artifacts and a run id, section names are regulator-neutral, no "compliant" branding; synthetic tests only (decision 0010).
- **One metric definition.** Evaluation does not re-implement statistics: it fits a monitor `Reference` on the reference sample (default the `train` role) over the score (quantile bins), the grade (categorical) and the declared features (CSI), and measures every other sample with `monitor.adapter.measure`, segmented by closing when `per_closing` is on. Rows and Spark DataFrames dispatch through the same adapter, so both engines and model monitoring agree by construction.
- **Grade table.** Per sample (and closing): rows, events, observed rate, expected rate (mean of the declared probability column, default the score), observed/expected, Brier within the grade. Grade order comes from the declaration or from the development's bands; an inversion is a pair of adjacent grades whose observed rate moves against the declared direction. Expected and Brier are unavailable (with a reason) when the probability is outside [0, 1]. Jeffreys/binomial tests and the volume gate stay in spec 82.
- **Tables.** `results` (sample, closing, metric, subject, value, count, status, reason), `distribution` (score and grade bin shares per sample against the reference, with PSI contribution), `grades`; each stamped with evaluation name, run id, config fingerprint and computation time, keyed for a Delta merge, written by an ordinary task — same shape as `mlops/selection/tables.py`.
- **Run artifact layout (the documentation contract).** `development/development.json`, `development/composition.json`, `selection/*.json` (spec 78), `evaluation/*.json`, `documentation/narrative.json`, `documentation/specification.json`, and optional `model/bricksmith_model.json`. The renderer reads only these; a missing optional artifact renders its section as "not recorded", never invented.
- **Numbers are never free text.** The declared narrative (purpose and use, population, target and maturity notes, limitations, inherent risk, materiality) is validated: a field containing a digit is refused, so every number in the document comes from an artifact.
- **Determinism.** Sorted keys, fixed float formatting, no timestamps except the explicit `generated_at` argument (defaults to now; tests pass a constant); HTML is self-contained (inline CSS, escaped text, no scripts or external links).
- **Model specification.** `model_specification(estimator, features, woe=None, scaling=None)` reads `coef_`/`intercept_` (linear: coefficients, and score points per WoE group under `{pdo, base_score, base_odds}` scaling) or `feature_importances_` (trees); anything else records the estimator class only. Logged as an artifact at training time, never recomputed by the renderer.
- **Publication.** `publish_document` logs `documentation/model_document.md` and `.html` to the run and tags the registered version with `bricksmith.documentation` = the run artifact URI of the HTML, through the existing `ModelStore.tag_version`. MLflow loads lazily.

### Assumptions

- The score evaluated for calibration is a probability of the event; a points score declares a separate `probability` column (Design, grade table).
- MLflow tracking and model version tags work on the free context, as `tests/remote/test_models.py` already proves (Validation).
- 2026-11-24 — **Corporate run findings (publication on Unity Catalog).** A supplementary corporate run tested this branch: the evaluation and the document path passed on Unity Catalog once three defects were fixed. The task 3.1 worker fixes all three, test first, before the free proof:
  1. On a Databricks workspace (`dbfs:` artifact store), `download_artifacts(run, "dir/file", dst)` writes `dst/file`, not `dst/dir/file`. `collect_run` must not assume the relative path is kept.
  2. A missing optional artifact surfaces only as `MlflowException: Failed to download artifacts from path '<file>'`. `collect_run` must treat that message as "absent" for optional inputs.
  3. Unity Catalog rejects tag keys containing `.`, `=`, `>`, `<`, `%`, `&`, `?` or `\`, so the documentation tag key `bricksmith.documentation` is refused. Use a key without reserved characters, such as `bricksmith_documentation`, and test the key against that character set.
  With these fixes, the corporate run logged the document, tagged the registered version with its location and regenerated the document byte for byte. That covers the remote registered-version proof the free tier cannot give (spec 88).
## Alternatives Considered

- **Re-implement the metrics inside evaluation.** Rejected: a second definition of KS/PSI/Brier would drift from model monitoring; the monitor core already serves rows and Spark.
- **Template engine (Jinja) for the document.** Rejected: a new dependency for a fixed document; plain string assembly with escaping is deterministic and import-light.
- **LLM narrative.** Out of scope by the Problem; numbers stay artifact-sourced.
- **Extend `render_card` in place.** Rejected: the card is a short summary consumed by the catalog; the technical document is a separate, larger artifact.
