## Problem

Found by the autopilot round 2 model scout (2026-11-24), reproduced on main e564870 with a synthetic pure-engine run: 12 monthly periods × 400 rows, grades "1".."11" whose risk rises strictly with the score, metric `grade_order`, `credit.grades` not declared.

`src/bricksmith/monitor/model/credit.py:38-41` orders undeclared grades with `sorted(...)` on their text (documented at `src/bricksmith/monitor/model/config.py:184`). The probe printed `order: ['1', '10', '11', '2', ...]` and `grade_inversions` was red (2–3) in 5 of 6 measured periods, yellow in the sixth.

Consequence: numeric grades 1..N with N ≥ 10 and no `credit.grades` produce false red grade-order results and alerts; with `gate.fail_on: red|critical` the run fails; the calibration table in details is misordered; nothing warns.

Proposal (decided by the autopilot as delegated owner): when every undeclared grade text parses as a finite number, order by numeric value; otherwise keep text order. Update the config docstring and the model guide; add a test with grades 1..11.

## Proposal

When `credit.grades` is not declared (or a present grade is left out of it), order the undeclared grades by numeric
value when every undeclared grade text parses as a finite number; otherwise keep today's text order. Declared grades
keep their declared order and still come first. Ties between texts with the same value (`"1"`, `"1.0"`) break by text,
so the order stays deterministic. The `Credit` docstring and the model guide state the rule; a unit test with grades
`1`..`11` proves `grade_inversions` stays green when risk rises with the grade.

## Out of Scope

- The model-evaluation grade order (`src/bricksmith/mlops/evaluation`), which ranks grades from development bands and does not sort grade texts.
- Natural ordering of mixed texts (`"A1"`, `"A10"`): a grade set with any non-numeric text keeps text order; declaring `credit.grades` remains the way to order it.
- Warning when grades are undeclared: the numeric rule removes the reported false inversions; a warning is a separate decision.

## Impact

### Product code this spec expects to touch

- `src/bricksmith/monitor/model/credit.py` — `grade_order`, the single place that orders grades for calibration and inversions.

- `tests/unit/monitor/model/test_model_credit.py` — the synthetic 1..11 grade test.

Behaviour change: a run whose undeclared grades are all numeric now measures inversions and orders the calibration
details by number; grade sets with any non-numeric text are unchanged. Result identities (`column=<grade column>=<grade>`) do not change.

## Design

- Owner decision (epic 109 Design, 2026-11-24): order undeclared grades numerically when every text parses as a finite number, else text order.
- `grade_order(config, present)` keeps `declared + undeclared`. A private helper parses a grade text with `float()` and accepts it only when `math.isfinite`; `nan`, `inf` and non-numeric texts make the whole undeclared set fall back to `sorted()` text order. The numeric sort key is `(value, text)`.
- Both callers (`grade_calibration`, `grade_inversions`) already go through `grade_order`, so the calibration details table and the inversion count change together. Pure and Spark engines both return text keys from `Frame.sums`, so the rule is engine-independent and needs no remote proof.

### Assumptions

- Grade texts reach `grade_order` as `str(value)` from `Frame.sums` (`category_text`), so an integer grade column reads `"1"`, `"10"`, and a float column `"1.0"`; `float()` parses both. — Design, Validation.

## Alternatives Considered

- Natural (digit-run) sort for every grade text: orders `"A10"` after `"A2"` too, but guesses an order for labels whose meaning the engine cannot know; rejected by the owner decision in favor of the all-numeric rule.
- Require `credit.grades` when the grade column is numeric: breaks existing configs and still needs the parsing rule; rejected.
- Order by observed mean score: data-dependent, can mask exactly the inversions the check exists to find; rejected.

## Open Decisions

- none — the owner decision in epic 109 Design settles the order rule.

## Risks

- A run that previously measured numeric grades in text order now reports different inversion counts and details order; the old results were wrong (false inversions), and result identities do not change, so stored alerts keyed on `grade_inversions` resolve or reopen on the next run as their values change. Documented in the guide.
- Numeric grades where a larger number means a better grade would read as inverted; they must declare `credit.grades` best to worst, as before.
