## Problem

Spec 118 (2026-11-24) added `tests/unit/monitor/test_spark_parity.py`, the only pure-vs-Spark parity tests that run without a workspace. They need a local `SparkSession`, but the project venv installs Databricks Connect, whose `pyspark` refuses local sessions (`RuntimeError: Only remote Spark sessions using Databricks Connect are supported`). So `uv run pytest` — the gate in `AGENTS.md` and CI — always skips them (`5 skipped`), and a Spark parity regression stays invisible to the gate. They pass only through an isolated environment: `uv run --isolated --no-project --with pyspark==4.0.1 --with-editable . --with pytest pytest tests/unit/monitor/test_spark_parity.py` (5 passed). Spec 120 will add more such tests.

Minimal fix proposed: add a gate step (script and CI job) that runs the tests needing a local Spark session in that isolated local-pyspark environment, and fails if they skip.

**Insumos**

- `tests/unit/monitor/test_spark_parity.py` (fixture `spark`, skip on session refusal)
- `pyproject.toml` (dependencies pulling Databricks Connect), `.github/workflows/`
- spec 118, conclude step 7; epic 121

## Proposal

Add an isolated local-pyspark gate step: `scripts/local_spark_check.py` (justfile `local-spark`) and a CI job `local-spark` run the `local_spark` tests under `uv run --isolated --with pyspark==4.0.1` and fail on any skip. The `local_spark` fixture gains a must-run switch `BRICKSMITH_REQUIRE_LOCAL_SPARK=true`, modeled on `BRICKSMITH_REQUIRE_KERNEL`.

## Out of Scope

- Changing the project environment's Databricks Connect dependency.
- Moving the parity tests or adding new ones (spec 120/157 own those).

## Impact

`tests/fixtures/unit.py`, `scripts/local_spark_check.py` (new), `scripts/registry.md`, `justfile`, `.github/workflows/ci.yml`, `docs/project/databricks-tests.md`. CI/scripts widening authorized by the human (epic 161 Design).

## Validation

- `python3 scripts/local_spark_check.py` with Java 17: 14 passed, exit 0; without Java: exit 1 (fixture fails instead of skipping).
- `uv run pytest`, ruff and pyright stay green; the plain run still skips the local_spark tests.

## Design

Human decision, option (a), recorded in epic 161 Design (2026-11-25). The script sets the switch, runs the two parity files, and also fails when the output reports a skip or no passed test.

## Alternatives Considered

Making the project env carry classic pyspark (rejected: conflicts with Databricks Connect); a pytest-only CI step without a script (rejected: no local entry point).

## Open Decisions

None; decided by the human.

## Risks

The CI job needs Java 17 (set up with setup-java) and a pyspark download; a runner without them fails the job by design.
