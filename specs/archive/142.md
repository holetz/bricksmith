## Problem

Every colored value enters the trend history, red ones included (`stability/metrics.py:205-210`), and
the `previous`/`rolling` baselines average every eligible period (`stability/metrics.py:96-106`). One past
anomaly therefore masks later ones: measured on the real `trend_check`, a clean history flags a 5.3σ jump as
red, while the same history with one earlier spike reports the same jump as green (deviation 0.06). The same
contamination shifts rolling baselines after a bad load, so the next periods are judged against corrupted
references.

## Proposal

- `trend.exclude: red | flagged | none` (default `red`): periods whose own light or trend status was red are
  not added to the history; their values are still stored and reported.
- `trend.fit: ols | theil_sen | huber` (default `ols` for compatibility, recommend `theil_sen`) and a robust scale
  (MAD) option, implemented in the pure core without new dependencies.
- `baseline.exclude: red | none` for `previous` and `rolling`: a period whose `volume_change` or PSI was red is
  skipped like an emptied period, taking the next eligible one (reuse the emptied-period mechanism,
  `stability/metrics.py:265-269`).
- Expose one internal "excluded periods" input so human marks (separate spec) plug into the same path.

## Out of Scope

- Human marking of periods (separate spec).
- Seasonality.

## Validation

- With `trend.exclude: red`, a red spike in history no longer masks a later jump.
- Theil–Sen and Huber fits match reference values on fixed synthetic series.
- A rolling baseline skips a red period and the next period's `volume_change` is judged against clean history.

## Design

- `TrendPolicy` gains `fit` (`ols` | `theil_sen` | `huber`, default `ols`), `scale` (`std` | `mad`, default `std`) and
  `exclude` (`red` | `flagged` | `none`, default `red`). The fits are pure Python in `trend.py`: no new dependency.
  The prediction standard error keeps the OLS leverage factor and Student-t quantiles; only the line and the residual
  scale change.
- `keeps(policy, light, trend)` is the single exclusion rule used by the stability metrics, the stored-history seed
  and the model monitor, so every history is filtered identically.
- `baseline.exclude: red | none` (default `none`, the old behavior) skips, per segment, periods whose `volume_change`
  or `psi` was red, for `previous` and `rolling`. `compute` takes `red_seed` (stored red periods before the window)
  and `excluded` (periods a human mark will name): `excluded` leaves every trend history and every
  `previous`/`rolling` baseline, reusing the emptied-period path of baseline selection.
- Durable rule: values stay stored and reported; exclusion only decides what future judgments learn from.

### Assumptions

- `baseline.exclude` defaults to `none` because the spec states no default and compatibility is kept; `trend.exclude`
  defaults to `red` as the spec states (a documented change of judgment, covered by the judgment fingerprint).

## Alternatives Considered

- Excluding at storage time (not writing red values to the history): rejected, results must stay complete and reported.
- A single dependency-based robust fit (scipy/statsmodels): rejected, the core stays pure Python.

## Open Decisions

- none — every item is decided above; human marks are a separate spec that only needs the `excluded` input.

## Risks

- Excluding red periods can hide a genuine permanent level shift: it keeps alerting until a human declares a
  regime change. Mitigate with the regime-change mark and by documenting the behavior.
