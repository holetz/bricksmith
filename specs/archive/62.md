## Problem

Reproduced 2026-10-23 by the autopilot conductor on main (af18d01), from the round Codex review (range e2742f7..af18d01):

`redact_text('passwords=["alpha", "beta"]')` → `passwords=<redacted>"alpha", "beta"]`; the same shape leaked on e2742f7 with `secret=["alpha", "beta"]` → `secret=<redacted>"alpha", "beta"]`. Cause: `src/bricksmith/ops/redact.py:139`, the unquoted-value matcher consumes only the `[`, leaving every list element in clear.

Consequence: a secret key whose value is a list (YAML flow sequence, JSON array, Python repr) prints each secret. Mask the whole bracketed value up to its matching `]` on the same line, keep #41's linear-time bound.

## Proposal

- When a sensitive key's value starts with `[`, mask the whole bracketed value up to its matching `]` on the same line (nested brackets and quoted strings respected); an unclosed list masks to the end of the line.
- Add tests for JSON arrays, YAML flow sequences, Python reprs, nesting, quoted `]`, unclosed lists; keep the linear-time bound.

## Out of Scope

- Non-sensitive keys with list values (`rows=[...]` is already handled by `_PATTERNS`).
- Multi-line lists.

## Impact

## Design

- **Single scan.** A helper `_bracketed_end(text, start)` walks forward once from `[`, tracking depth and quote state, stopping at the matching `]` or at a newline; it returns the end index. The assignment sweep then resumes after it, so every character is scanned once (linear).
- Epic 164 decision: 60 → 61 → 62 run in series on these files.

## Alternatives Considered

- A regex with nested-quantifier groups: rejected, risks backtracking and breaks the linear bound.

## Open Decisions

- none — the issue fixes the expected behavior.

## Risks

- A quote character inside an unquoted list element could hide a later `]`; the fallback masks to end of line, which over-masks rather than leaks.
