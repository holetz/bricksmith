## Problem

`ModelStore` keeps each alias history in a registered-model tag `bricksmith_history_<alias>` (`src/bricksmith/mlops/store.py`, `TAG_HISTORY`, `record_history`). Alias names are validated by `_ALIAS = ^[A-Za-z][A-Za-z0-9_-]{0,62}$`, so an alias may contain `-`, and the tag key then contains `-` too.

Unity Catalog refuses some punctuation in tag keys. Spec 80's corporate run (archive 80, Design) found the refused set to be `.`, `=`, `>`, `<`, `%`, `&`, `?` and `\`. `-` is not in that set, but no run has written a history tag for an alias that contains `-`, and no unit test checks the generated key against the refused set. Spec 94 (2026-11-24) parked this as a discovery and kept it out of scope.

What the fix has to make impossible: a valid alias producing a tag key that Unity Catalog refuses. That means either a unit test that checks every key derived from the `_ALIAS` alphabet against the refused set, or a key encoding that cannot contain refused characters, plus Unity Catalog evidence of a `-` alias on the corporate follow-up.

**Insumos**

- `src/bricksmith/mlops/store.py`: `_ALIAS`, `TAG_HISTORY`, `history`, `record_history`
- `tests/unit/mlops/test_models.py`: the Unity Catalog-faithful fake added by spec 94 (256-character values, 50 tags)
- `tests/unit/mlops/documentation/test_publish.py`: the existing tag-key check against `. = > < % & ? \` (spec 80)
- spec 94 `## Discoveries` and `## Out of Scope`, spec 80 `## Design` corporate findings

## Proposal

- A unit test proves every alias-history tag key `ModelStore` can generate from the `_ALIAS` alphabet (including `-`) contains no character Unity Catalog refuses in a tag key.
- The key derivation is unchanged when the test proves no valid alias yields a refused character, and fixed when it does not.

## Out of Scope

- Writing a history tag for a `-` alias on a corporate Unity Catalog workspace: no credentials on this machine; recorded as not run in `## Outcome`.
- Changing the alias grammar or the event tag keys.

## Impact

### Product code this spec expects to touch

- `src/bricksmith/mlops/store.py` — only if the derivation yields a refused key.
- `tests/unit/mlops/test_models.py` — the key check over the alias alphabet.

## Validation

- `uv run pytest tests/unit/mlops/test_models.py -q` passes, including the new key check.
- The new check fails when a refused character is added to the alias alphabet (proved against a mutated pattern).

## Design

- Rule: a history tag key is `TAG_HISTORY + alias`; `_ALIAS` admits `[A-Za-z0-9_-]` only, and `TAG_HISTORY` is `bricksmith_history_`. Unity Catalog's refused tag-key set (spec 80 corporate run) is `. = > < % & ? \`. The sets are disjoint, so no encoding is needed; the test pins this so widening `_ALIAS` cannot silently break Unity Catalog.
- The test builds keys through `record_history` on the fake client for every alphabet character, and asserts each stored key avoids the refused set and matches `^[A-Za-z0-9_-]+$`.
- decision: unit half only — epic 164 Design records it; no credentials for the corporate run.

## Alternatives Considered

- Encode the alias into the key (hex): rejected, the characters are already accepted and it would break reading existing tags.

## Open Decisions

- none — the corporate-workspace evidence is deferred, not undecided; it is recorded as not run in `## Outcome`.

## Risks

- A `-` alias could still be refused by Unity Catalog in a way the spec 80 set did not reveal. ACCEPTED — the unit check pins the known set; the corporate follow-up stays open.

## Handoff

Read `_ALIAS`, `TAG_HISTORY` and `record_history` in `src/bricksmith/mlops/store.py`; the fake client is in `tests/unit/mlops/test_models.py`.
