## Problem

Spec 155 (epic 139) made stability PSI limits sample-size aware (χ²-based floor, minimum rows per bin, optional smoothing), but model-monitoring CSI, which shares `psi_terms`, still judges against fixed limits. Small model segments therefore keep the false-alarm behavior measured in epic 139 (a 30-row sample red on PSI 84% of the time under no change).

## Proposal

- Reuse the stability sample-size rule for CSI and score PSI in model monitoring, with the same declaration keys and stored effective limits.

## Out of Scope

- Changing any model-monitoring default. Existing declarations keep fixed limits, no per-bin row gate and the `epsilon` share floor; ruled out because decision "#160 default" of epic 161 keeps existing results unchanged.
- Duplicating the floor in the model package. The sampling-noise rule stays in `monitor/stability/metrics.py`; the model engine calls it.
- A model-specific `min_rows_per_bin` default of 10. Deferred: raising it would turn existing `light` results into `insufficient_volume` without a declaration change.
- Smoothing of `stability` (multi-period) PSI in `monitor/measure.py`; the model engine does not enable that metric.

## Impact

### Product code this spec expects to touch

- `src/bricksmith/monitor/stability/metrics.py` — expose the noise-floor rule so the model engine reuses it
- `src/bricksmith/monitor/model/config.py` — declare `psi_limits`, `min_rows_per_bin`, `psi_smoothing`
- `src/bricksmith/monitor/model/engine.py` — carry the sample on each distribution item and judge with effective limits
- `src/bricksmith/monitor/model/credit.py` — carry the sample and smoothing on the exclusion-mix PSI
- `src/bricksmith/monitor/measure.py` — optional Laplace smoothing read from `metric_config`
- `docs/how-to/model-monitoring.md`, `docs/how-to/stability.md` — document the keys and drop "CSI keeps fixed limits"

## Validation

- `uv run pytest tests/unit/monitor -q` passes, including the stability sample-size tests, the model parity tests and the new model tests.
- A model declaration with no new key yields byte-identical `green_limit`/`red_limit`/`light` as before (asserted by a regression test).
- With `psi_limits: sample_size`, a 30-row period over a 10-bin CSI stores limits above the declared 0.10/0.25 and is not red under no change.
- `uv run ruff check && uv run ruff format --check && uv run pyright` are clean.

## Design

- **Same keys, same vocabulary.** `psi_limits` (`fixed` | `sample_size`), `min_rows_per_bin` (int >= 0) and `psi_smoothing` (`epsilon` | `laplace`), parsed with the stability constants. Model defaults are `fixed`, `0`, `epsilon` so existing results do not change (epic 161 decision "#160 default"); stability keeps its own defaults. Evidence that no default flip is warranted: the stability migration note in `docs/how-to/stability.md` documents result changes for existing declarations, which this epic decided to avoid for model monitoring.
- **One rule.** `effective_limits` in `stability/metrics.py` splits into a config-free `noise_floor(limits, sample)` (the `chi2 * (1/n + 1/m)` raise, never lowering a limit); `effective_limits` keeps its signature and calls it. The model engine calls `noise_floor` for metrics `psi`, `csi`, `grade_psi`, `exclusion_psi` when `psi_limits == sample_size`.
- **Sample source.** `Item` gains an optional `sample` (current rows, baseline rows, bins). For measured distributions: `m.count`, the frozen spec's reference rows, and the number of bins in the measurement detail; for `exclusion_psi`: the two count maps. `sample_of` is reused where inputs are count maps.
- **Stored effective limits.** `_result` in the engine writes the effective limits into `green_limit`/`red_limit`, as stability does.
- **Row gate.** `min_rows_per_bin` raises the minimum count to `ceil(min_rows_per_bin * bins)` for these metrics, as in stability `_judge`; `0` disables it.
- **Smoothing.** `psi_smoothing: laplace` passes `LAPLACE_COUNT` to `psi_terms` through a transient `metric_config` key set on the measured reference copy, so the frozen binning and its fingerprint are untouched.
- **Fingerprint and serialization.** The keys appear in `to_dict` only when non-default, as in stability, so stored declarations stay identical; they are not part of `binning_fingerprint`.

### Assumptions

- Spark and row frames both expose bin counts via `Measurement.detail["bins"]` (parity tests cover this) — supports the sample task.

## Alternatives Considered

- Flip the model defaults to match stability: rejected by the epic's decision; it would change existing results silently.
- Copy the floor into `monitor/model`: rejected; two copies of the statistical rule would drift.
- Put the keys under a nested `psi` block: rejected; the epic asks for the same declaration keys as stability.

## Open Decisions

- none — the epic's "#160 default" decision settles the defaults and the reuse rule.

## Risks

- A grade or exclusion PSI with one bin makes `bins < 2`; `noise_floor` already returns the limits unchanged then. Mitigated by reusing the guard.
- Laplace smoothing changes values only when declared; ACCEPTED — opt-in.
- Stale stored `Reference` bodies lack the smoothing key; mitigated by `metric_config.get` with a `0.0` default.

## Outcome

Model monitoring now accepts the stability declaration keys `psi_limits`, `min_rows_per_bin` and `psi_smoothing` for `psi`, `csi`, `grade_psi` and `exclusion_psi`. The sampling-noise floor is the stability rule, extracted as `noise_floor` in `monitor/stability/metrics.py` and reused by the model engine; the effective limits are stored in `green_limit`/`red_limit`. Model defaults are `fixed`, `0` and `epsilon`, so existing results are unchanged (epic 161 decision "#160 default"). Left out: changing any model default, and smoothing of the multi-period `stability` metric. The local-pyspark parity tests were skipped here (pyspark not installed); the smoothing hook sits in the shared `measure._distribution`, which both engines use. Docs: `model-monitoring.md` and `stability.md` updated. Reviewed, ready for merge.
