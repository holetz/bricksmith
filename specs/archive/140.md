## Problem

The trend check standardizes the current residual by the fit's residual standard deviation
`sqrt(SSE / (k - 2))` (`src/bricksmith/monitor/trend.py:85-116`) and compares it with fixed normal cut-offs
(2.0 / 3.0). An extrapolated point also carries the uncertainty of the fitted line itself (the leverage term
`sqrt(1 + 1/k + (k - x̄)² / Sxx)`) and, with k ≤ 12 points, the residual follows a Student-t with k - 2
degrees of freedom, not a normal. Measured on the real `trend_check` with pure i.i.d. noise (no anomaly,
direction `both`): window 12 flags 12.0% of periods yellow-or-worse and 2.9% red, against a nominal 4.6% /
0.27% (about 11x the red rate); at the minimum of 6 points it is 22% / 9.5% (about 35x). Each red opens a
`trend` alert immediately (`stability/metrics.py:514-516`), so a table with tens of segments and columns
produces trend alerts every run.

The opposite failure exists too: on a near-constant series the residual sigma collapses, so one extra row on
a flat `row_count`-like series gives `deviation = inf` and red (`trend.py:112-114`), and a 0.1% move on a very
stable series is red. There is no minimum effect size. Finally, for periods at the start of a rewritten window
the trend history is built only from in-window periods (`stability/metrics.py:265-281`), so a re-judged window
reports `insufficient_history` for periods that had enough history when first judged.

## Proposal

- Standardize by the prediction standard error `s * sqrt(1 + 1/k + (x0 - x̄)² / Sxx)` and judge with
  Student-t quantiles at k - 2 degrees of freedom; express `yellow`/`red` as two-sided (or one-sided per
  direction) tail probabilities with defaults equivalent to today's intent (≈ 95.4% / 99.7%), keeping `2.0`/`3.0`
  accepted as sigma-equivalents for backwards compatibility.
- Add `trend.min_abs_change` and `trend.min_rel_change` (default off for drift metrics, a small relative floor
  for volume metrics): a deviation that does not exceed the floor is never yellow/red; this also replaces the
  `inf` deviation of a zero-variance history.
- Add `trend.transform: none | log` (log1p for counts) so multiplicative growth is a straight line.
- Feed the trend from the stored results/profiles of the `trend.window` periods before the window start, so a
  re-judged window yields the same trend status as the first judgment.
- Store `trend_sigma`, `trend_lower` and `trend_upper` (band in the original scale) on result rows (schema
  evolution) so dashboards can draw the band.
- Apply the same core in model monitoring (`monitor/model/engine.py:885-905`), which shares `trend_check`.

## Out of Scope

- Robust fitting and exclusion of anomalous history (separate spec).
- Seasonality (separate spec).
- Changing the persistence policy of trend alerts.

## Validation

- A seeded simulation test on i.i.d. normal noise shows yellow/red rates within tolerance of the nominal rates
  for k = 6 and k = 12.
- A flat history plus a 1-row change is green with the default relative floor.
- A log-transformed exponential series is green; the same series untransformed is not.
- Re-judging a window gives the same trend status as the first run for every period with enough stored history.

## Design

- **Statistic.** Fit OLS on the last `window` prior values; the prediction standard error is
  `s * sqrt(1 + 1/k + (k - x̄)² / Sxx)` with `s = sqrt(SSE/(k-2))`. The deviation is `residual / se` (a t statistic with
  `k - 2` degrees of freedom).
- **Thresholds.** `yellow`/`red` stay sigma-equivalents (2.0 / 3.0): each maps to the normal tail `q = 1 - Φ(z)` and the
  critical value is the Student-t quantile `t(1 - q, k - 2)`. One tail per direction `higher`/`lower`; for `both` the
  two-sided probability `2q` gives the same quantile. Pure Python (incomplete beta by continued fraction + bisection,
  `statistics.NormalDist` for the normal), no new dependency.
- **Floor.** A residual with `|residual| <= max(min_abs_change, min_rel_change * |expected|)` is never yellow/red.
  `min_abs_change` defaults to 0 and `min_rel_change` to 0.01. A zero-variance history reports `deviation = None`
  (never `inf`); it is red only when the residual exceeds the floor.
- **Transform.** `transform: none | log` fits on `log1p`; expected and band come back in the original scale; a value
  `<= -1` makes the transform inapplicable and the point `insufficient_history`.
- **Band.** `trend_sigma` (prediction se, fit scale), `trend_lower`, `trend_upper` (red-level interval, original scale)
  on every result row in both engines; added through the existing `evolution` write option.
- **Pre-window history.** The stability engine seeds the trend history of each series from the stored results of
  the `trend.window` periods before the window start, so a re-judged window reproduces the first judgment.
- The judgment fingerprint already hashes `config.to_dict()["trend"]`, so new policy keys re-judge the window once.

### Assumptions

- The default 1% relative floor is global (not per metric): drift metrics sit near zero where a 1% floor is inert
  (Design, Floor).

## Alternatives Considered

- Fixed per-metric floors only: rejected, a relative floor adapts to the series scale.
- scipy/numpy quantiles: rejected by the epic's no-new-dependency decision.

## Open Decisions

- none — every decision is settled by the proposal and the epic's pure-Python policy.

## Risks

- Existing dashboards and gates see fewer trend alerts after the change; the judgment fingerprint changes and
  the window is re-judged once (alerts superseded). Document it as a migration note.

## Discoveries

- decision: yellow/red stay sigma-equivalents mapped to Student-t quantiles; no separate tail-probability keys — keeps backwards-compatible config, epic autonomy policy
- decision: default min_rel_change=0.01 global, min_abs_change=0 — simplest default satisfying the flat-series criterion

## Outcome

Shipped: the stability and model-monitoring trend check now standardizes by the prediction standard error
(`s * sqrt(1 + 1/k + (k - x̄)² / Sxx)`) and judges against Student-t quantiles at `k - 2` degrees of freedom
(pure Python, no new dependency); `yellow`/`red` remain sigma-equivalents. New policy keys `min_abs_change`,
`min_rel_change` (default 1%) and `transform` (`none | log`); a zero-variance history reports no deviation instead of
infinity. Results of both engines carry `trend_sigma`, `trend_lower` and `trend_upper` (schema evolution). The
stability engine seeds the trend history from stored results before the window start so re-judged windows match the
first judgment. Seeded simulations show nominal yellow/red rates for k = 6 and 12. Documented with a migration note.

Left out: robust fitting and seasonality (separate specs), tail-probability config keys (sigma-equivalents kept), seeding
the model-monitoring engine (its history is not window-truncated), and a per-metric floor default.
