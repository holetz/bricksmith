## Problem

On a Windows checkout of main @105c814, the local gate (`uv sync --locked`, `uv run ruff check`, `uv run pyright`, `uv run pytest`) is not green, and the spec store can resolve to the wrong backend. Three independent causes were observed: `.claude/quenching.json` is committed as a symlink (mode 120000) that Windows without symlink privilege checks out as a text file; `uv run pyright` reports 29 reportMissingImports for optional heavy integrations that the default groups deliberately omit; two tests assume POSIX (a `venv/bin/python` path and permission to create symlinks).

## Proposal

Fix each cause in its own small PR so that a fresh Windows checkout runs the unchanged gate command to green without optional extras, while Linux/CI behavior stays identical. Order: ship the regular config file first (the spec store must resolve to `backend: git` before any other spec is tracked from Windows), then the type-check and test-portability fixes in parallel.

## Out of Scope

Changing CI workflows, hook scripts or the gate command; adding heavy integrations to default dependency groups; the Windows hook interpreter and CI billing issues (tracked as human decisions in epic 6).

## Validation

On a Windows checkout without symlink privilege: `cq specs config` reports `backend: git`; `uv sync --locked && uv run ruff check && uv run pyright && uv run pytest` exits 0 with no optional extras installed. On Linux the same gate stays green and skipped tests are only the documented platform-specific ones.

## Design

Round 1 of the autopilot run started 2026-10-15 restores the local gate on Windows checkouts
before epic 5 resumes.

**Autonomy policy (dated 2026-10-15).** The owner's `/quenching:specs:autopilot` invocation of
2026-10-15 authorizes, for every member of this round (specs 34, 35, 36), forced execution, push,
pull request and merge after a verifier PASS. It does not authorize widening a grant or any surface
that executes code (hooks, CI, `allowed-tools`, agent tools) nor changing the autonomous protocol;
those go to the human epic 6.

**Waves.** Wave 1: spec 34 alone (every worker worktree needs the regular config file before `cq`
reaches the git spec store). Wave 2: specs 35 and 36 in parallel (no shared files).

**Bootstrap note.** Until spec 34 merges, a fresh worktree checks `.claude/quenching.json` out as
symlink text and `cq` falls back to the github backend. Spec 34's worker writes that file as its
first change, before any other `cq` call inside its worktree.

**Amendment (2026-10-15) — CI refused by billing.** GitHub Actions does not start the repository's
only check (`checks`): every run ends in seconds with the annotation "The job was not started
because recent account payments have failed or your spending limit needs to be increased" (main
run 38615145589, PR #6 run 38814122581). That red check carries no code signal. Under the forced
merge this policy authorizes, a member PR whose only failing check is that billing-refused job —
re-confirmed from the run's annotation on each PR — merges on its verifier PASS and the local gate.
Any other failing check still blocks the merge. Restoring CI is spec 38 in the human epic 6.
