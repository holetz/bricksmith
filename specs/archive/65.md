## Problem

Turning a metric value into a decision needs more than one threshold. Monitoring practice uses traffic lights with explicit states for "cannot judge" (no baseline, no data, too few rows, no rule), checks a series for a sudden departure from its own trend, and opens an alert only when a bad state persists, escalating and closing it by rule. bricksmith has single-threshold `AlertRule`s only. Without a shared core, data stability and model monitoring would each grow their own banding and alert logic, as the reviewed reference did.

## Proposal

Add three pure, engine-free modules to `bricksmith.monitor`:

- `limits`: `Limits(green, red, direction, center=0.0)` and `classify(value, limits, ...) -> Light` with states `green`, `yellow`, `red` and suppressed states `no_baseline`, `no_data`, `insufficient_volume`, `no_rule`; a numeric `rank` (-1 suppressed, 0, 1, 2) for sorting and dashboards.
- `trend`: `trend_check(history, current, *, window, min_points, yellow, red, direction) -> Trend` fitting ordinary least squares on the last `window` prior values and standardizing the current residual.
- `persistence`: `PersistencePolicy(yellow, red, close_after, immediate_red, recurrence)` and `alert_spans(series, policy) -> list[AlertSpan]` replaying an ordered status series into opened, escalated and closed alerts.

## Out of Scope

- Wiring these into the BS-13 `AlertRule` evaluation (follow-up spec "Adopt the shared limits and persistence in model monitoring").
- Persisted alert state edited by people (follow-up spec on the alert workflow).

## Impact

- `src/bricksmith/monitor/limits.py`, `trend.py`, `persistence.py` — new.
- `src/bricksmith/monitor/__init__.py` — exports.
- `tests/unit/monitor/test_limits_trend_persistence.py` — new.

## Validation

- Hand-derived tests: boundaries are inclusive for green and yellow (`higher`: green when `v <= green`, yellow when `v <= red`, red otherwise; `lower` mirrored; `both` on `|v - center|`), invalid limit orders raise `MonitorError`, suppressed states win over values.
- Trend: a perfect line gives zero deviation; a jump of 3+ residual sigmas is red; a zero-variance history with an equal value is green and a different value is red in the worse direction only; fewer than `min_points` is `insufficient_history`.
- Persistence: K yellow-or-worse opens a warning, M reds open (or escalate to) critical, severity never downgrades, `close_after` greens close, suppressed periods are skipped without breaking or counting, a reopen within `recurrence` periods is flagged.

## Design

- `Light(status, rank, reason)`; `classify` order: `no_data` (value None) → `insufficient_volume` (count < min_count) → `no_baseline` (flag) → `no_rule` (limits None) → band.
- Directions: `higher` (higher is worse, `green <= red`), `lower` (`green >= red`), `both` (distance from `center`, `0 <= green <= red`).
- Trend: x = 0..k-1 over the last `window` usable prior values; slope/intercept by OLS; expected = fit at x = k; sigma = sqrt(SSE / (k - 2)); z = (current - expected) / sigma; sigma = 0 gives z = 0 when equal, otherwise ±inf. Direction filters the side that counts. Defaults: window 12, min_points 6, yellow 2.0, red 3.0.
- Persistence over statuses ordered by period; suppressed statuses are skipped. Counters of consecutive yellow-or-worse, red and green. Open critical when `red` consecutive reds (or one red with `immediate_red`), else warning at `yellow` consecutive yellow-or-worse; while open, reaching the red condition escalates; `close_after` consecutive greens close. `0` disables a trigger. Defaults: yellow 3, red 2, close_after 3, recurrence 12.
- Every type has `to_dict`; outputs are deterministic for equal inputs.

## Alternatives Considered

- Several single-threshold `AlertRule`s per metric. Rejected: no suppressed states, no persistence, and two rules can both fire for one value.

## Open Decisions

- none — defaults follow common industry practice (PSI 0.10/0.25, 2/3 sigma) and are configurable.

## Risks

- OLS on very short histories is noisy; `min_points` guards it.

## Handoff

Pure modules; no Spark import at module level. Keep `monitor/__init__` light.
