## Problem

Found by a supplementary corporate run (2026-11-24, classic standard-access cluster, DBR 19.x):

- **Classic-cluster mode cannot start when the selected profile also carries `serverless_compute_id = auto`.** That is the documented default profile setup. `clients._spark` sets `cluster_id` on an SDK config that already holds the profile's serverless key, and Databricks Connect refuses both (`Can't set both cluster id and serverless_compute_id`). Assigning `None` does not help: SDK config attributes stringify on assignment, so the value becomes `"None"` and Connect raises `ValueError: Invalid serverless_compute_id value. Must be 'auto'.` As a result, `cluster:<id>` is unusable with any serverless-configured profile.
- **The `remote` dependency group pins `databricks-connect<18`.** A DBR 19.x classic cluster works with Connect 19.4.0 (UDF, `mapInPandas`, `applyInPandas`, `applyInArrow`, UDTF, Unity Catalog registry probes all passed), so classic compute on recent runtimes needs a wider range and a regenerated `uv.lock`.
- **`bricksmith env check` reports only the exception class** (`compute-tested failed: ValueError`). That hid the actionable Connect message; the preflight should carry the sanitised message.
- **A stray local `mlflow.db`** appears in the working directory during Unity Catalog model create/delete with explicit `databricks`/`databricks-uc` URIs, and after the remote model test. Its source is not isolated: find it, or confine the tracking store to a temporary directory.

Files: `src/bricksmith/clients.py`, `tests/unit/core/test_clients.py`, `pyproject.toml`, `uv.lock`, the env check module. Prerequisite for the corporate proof of spec 91.

## Proposal

- `Clients.spark()` on `cluster:<id>` works with a profile that also carries `serverless_compute_id = auto`: the inherited serverless key is dropped before the cluster id is set.
- The `remote` dependency group admits Databricks Connect 19 (`>=17.3,<20`) and `uv.lock` is regenerated to match.
- The `compute-tested` preflight stage reports the failure class plus a redacted, bounded message instead of the class alone.

## Out of Scope

- The stray local `mlflow.db` created during Unity Catalog model operations: its source is not isolated, so confining it needs its own investigation. Deferred to a follow-up spec; recorded in `## Discoveries`.
- Changing the `spark` extra (`databricks-connect`, unpinned) — it already admits any version.
- Selecting the Connect version from the cluster runtime: the range is only widened here.

## Design

- **Drop the key, never assign `None`.** SDK config attributes stringify on assignment, so `None` becomes `"None"` and Connect raises `Invalid serverless_compute_id value`. The key is removed from the config's own attribute dict (`config.as_dict().pop(...)`), the way Connect itself clears it. Alternative weighed: building a fresh `Config` from explicit fields — rejected, it would lose the profile's auth settings.
- **Test with a stringifying fake.** The unit test mirrors the SDK's assignment behaviour so an assignment of `None` fails it; a plain namespace would pass for the wrong reason.
- **Connect range `>=17.3,<20`.** Connect 19 ran UDF, `mapInPandas`, `applyInPandas`, `applyInArrow` and UDTF probes on DBR 19.x classic compute; the lower bound stays for DBR 17.3. The lock is regenerated with `uv lock`.
- **Preflight message is redacted and bounded.** It goes through `bricksmith.ops.redact.redact_text` and is cut to a short single line, so secrets and row data never reach the report; the class name stays the first token.
- Binding: AGENTS.md "Free-first tests", `docs/project/databricks-tests.md` (explicit context, no `DEFAULT` fallback); epic 85 `## Design` (no organisation, host or profile in any artifact; synthetic tests).

## Alternatives Considered

- Pin one Connect version per runtime: rejected, a range keeps one lock file and Connect is backward compatible with older runtimes in the tested span.
- Ask users to strip `serverless_compute_id` from their profiles: rejected, serverless-configured profiles are the documented default setup.

## Open Decisions

- none — the stray `mlflow.db` is deferred to a follow-up (Out of Scope), and nothing else is undecided.

## Risks

- Connect 19 is untested against every runtime in the range. Mitigation: free-context serverless proof and the recorded classic DBR 19.x run; ACCEPTED — runtimes between are covered by Connect's compatibility policy.
- `as_dict()` returning a copy in a future SDK would make the pop a silent no-op. Mitigation: the unit test pins the attribute behaviour, and a real SDK config check in the test is added when the extra is installed.
- A redacted message may still be long or sensitive. Mitigation: redaction plus a hard length cut.
