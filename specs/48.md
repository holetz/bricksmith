## Problem

Quality checks disagree between row and Spark execution or omit requested failure evidence. Verified in source on 2026-10-17:

- checks_spark.py:94-97: accepted_values with values=[1, None] and allow_null=True evaluates invalid non-null 2 through SQL UNKNOWN, so filtering drops the invalid row. checks_rows.py:72-83 correctly rejects it. Nullable declarations must not allow other non-null values; audit condition_sql in checks.py for the same three-valued-logic contract.
- checks.py:169-170: from_dict wraps require_match and allow_null in bool(), so the string 'false' becomes True and can weaken null rejection. Reject non-boolean declarations with QualityError for both flags, including direct construction; preserve actual True/False and omitted defaults. Cover JSON/TOML loading and serialization.
- checks_spark.py:128 casts the newest timestamp to long seconds while checks_rows.py:113 retains microseconds. A newest timestamp 12:00:00.900000, now 12:00:01 and threshold 0.2 seconds must pass both engines. Include exact boundary, stale, date, timezone and empty/all-null cases without changing the availability contract; audit condition_sql freshness precision as well.
- checks_spark.py:44-57 and checks_rows.py:32-42 fail grain checks for null keys but sample duplicate groups only. With a positive sample_limit, null-only and mixed failures must provide bounded deterministic offending keys, including composite partial-null keys. Default sampling remains disabled; preserve counts and status.

Capture one medium fix because implementation/tests overlap: src/bricksmith/quality/checks.py, checks_rows.py, checks_spark.py; tests/unit/quality/test_checks.py; tests/remote/test_quality.py; quality guide only if needed. Depend on reused spec #46 to avoid concurrent edits. Synthetic row/Spark parity regressions must verify verdicts, counts, boundaries and samples. Coordinate all remote runs serially with the conductor. This capture does not approve or execute the work.

## Proposal

Make row and Spark evaluation agree on four contracts, in `checks.py`, `checks_rows.py` and `checks_spark.py`:

- accepted_values with `allow_null` rejects every non-null value outside `values`, including through three-valued logic (Spark filter and `condition_sql`).
- `require_match` and `allow_null` accept only real booleans, in direct construction and `from_dict` (JSON/TOML); otherwise `QualityError`.
- freshness compares at microsecond precision in both engines and in `condition_sql`, with dates read as UTC midnight.
- grain checks with a positive `sample_limit` sample bounded, deterministically ordered offending keys for duplicate groups and null-containing keys alike; default sampling stays disabled; counts and status do not change.

## Out of Scope

- none — scoped to the four findings; availability contract, check kinds and report shape are unchanged. Naive `timestamp_ntz` handling on Spark is parked as a discovery.

## Design

### Mapa de dependências

- `checks_spark.py` and `checks_rows.py` import `Check`, `_verdict`, `_unavailable` from `checks.py`; `run_check` dispatches to them. `condition_sql` feeds storage `input_checks`/`target_checks` (tests in `tests/unit/quality/test_checks.py` assert its text). Spec 53 (sample order) is merged; its `_value_key` ordering is reused.

Accepted values on Spark: invalid = `NOT (coalesce(col IN values, false) OR col IS NULL)` with allow_null, else `NOT coalesce(col IN values, false)`; `condition_sql` becomes `(coalesce(listed, false) OR col IS NULL)`.

Booleans: `__post_init__` rejects non-bool `require_match`/`allow_null`; `from_dict` passes raw values through.

Freshness: Spark uses `unix_micros` of the max cast to timestamp (dates via `datediff * 86400e6`, UTC); rows use integer microseconds of the timedelta; both compare against `round(max_age_seconds * 1e6)`. `condition_sql` uses `unix_micros`.

Grain samples: union of duplicate-group keys and null-containing keys, distinct, ordered nulls first, limited.

## Alternatives Considered

- Float seconds with a tolerance: rejected, boundaries stay inexact.
- Coercing `'false'` via a string parser: rejected, declarations must be unambiguous.

## Open Decisions

- none — every item is decided from the finding evidence.

## Risks

- No local pyspark: Spark code is covered by remote tests only; mitigated by keeping the Spark expressions minimal and reporting unavailable remote proof.
- `unix_micros` needs Spark 3.1+; Databricks runtimes satisfy this.
