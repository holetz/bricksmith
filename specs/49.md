## Problem

Comparison diagnostics report mismatch counts but cannot identify the largest numeric errors. src/bricksmith/quality/report.py:76 stores only name and mismatches; quality/spark.py:108 aggregates counts and :114 orders samples by key. quality/rows.py has the same count-first contract. Operators need a bounded opt-in diagnostic that distinguishes small differences from large deviations without collecting full datasets.

Add a small backward-compatible public option to row and Spark comparison: report the maximum finite absolute deviation among mismatches for each numeric column, and, only with explicit sample_limit, provide bounded samples ordered by largest deviation with deterministic key tie-breaking. Keep existing mismatch verdict/tolerance logic and default serialization/output behavior; old reports remain readable and new opt-in reports round-trip. No raw samples by default and no new heavy root dependency. Public DQX supplies broad inspiration for detailed quality failure information (https://github.com/databrickslabs/dqx); this requirement and implementation are independently derived for Bricksmith.

During development make the numeric contract explicit: exclude null/non-numeric/bool/NaN/infinity pairs and non-finite deviations from the finite maximum/ranking while retaining their existing mismatch counts; no eligible mismatch yields an absent/null metric rather than zero; define exact finite Decimal handling and supported range without silent overflow/precision loss; define stable tie order consistent across row/Spark, including composite keys. Sample only mismatches, not matching pairs inside tolerance. Cover positive/negative finite numbers, zero, Decimal precision, null/NaN/infinity, empty/matching inputs, ties, sample bounds and compatible JSON round-trip with synthetic tests. Preserve default key-ordered sample behavior unless the new option is enabled. No drift policy, new mismatch thresholds, dashboards or storage changes.

Expected files: src/bricksmith/quality/report.py, rows.py, spark.py, public API surface as needed; tests/unit/quality/test_compare.py; tests/remote/test_quality.py; docs/guide/quality.md. Depend on the quality-check fix slice to serialize shared remote tests/docs. Remote aggregation stays on Spark; collect only aggregate scalars and bounded samples. All remote runs coordinate serially with the conductor. Complexity medium is a capture estimate; re-scope explicitly if a fully general Decimal contract exceeds a single independently verifiable PR. This capture does not approve or execute the work.
