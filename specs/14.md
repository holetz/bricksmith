> # BS-07. Registry, naming and semantic metadata
> 
> Implements BS-07.1 to BS-07.4 of [Epic 0001](../epics/0001-bricksmith-library.md) under
> [decision 0007](../decisions/0007-registry-mechanism-presets-seed.md). Stdlib only, no Spark.
> 
> ## Decisions closed
> 
> - Project data is TOML with an integer `version = 1`; unknown keys and versions are rejected.
> - Two files: the registry (`registry/columns.toml`) and an optional preset (`registry/naming.toml`).
>   Defaults are neutral: snake case, 128 characters, a short SQL reserved list, no vocabulary.
> - A preset layers over the defaults per scope key; no global state, everything is passed in.
> - Sensitivity is `unclassified` (the explicit default) or one of the preset's levels.
> - A table lists the columns it uses; a column undefined in the registry needs a `type` in the
>   override, otherwise it is `unknown`.
> - Finding ids are `<rule>:<subject>` (for example `naming.case:column:OrderId`), independent of
>   message text. Severity per rule or glob: `error`, `warning`, `off`; unlisted rules are errors.
> - Ratchet: the baseline JSON lists tolerated error ids; baselined errors pass, new ones fail,
>   fixed ones are reported as stale. Warnings never fail.
> - Exceptions need `finding` (glob on ids), `reason` and `expires` (ISO date, inclusive). An
>   expired exception stops suppressing and adds an `exception.expired` error.
> - Metadata merging keeps unrelated keys; only the `bricksmith.*` property namespace is owned.
> 
> ## Public contract
> 
> `load_registry`/`parse_registry` -> `Registry`; `load_preset`/`parse_preset`/`default_preset` ->
> `Preset`; `run_check(registry, preset, baseline, today)` -> `CheckReport` (`ok`, `to_text()`,
> `to_json()`, findings sorted by id); `load_baseline`, `write_baseline`; `table_metadata`,
> `merge_comments`, `merge_properties`, `sensitivity_coverage` (classified/unclassified/unknown).
> CLI: `bricksmith registry check [--registry --preset --baseline --write-baseline --today --json]`;
> exit 0 when ok, 4 when a finding fails, 4 on malformed files.
> 
> ## Rules
> 
> `naming.{case,token,prefix,suffix,length,reserved}`, `registry.{type_missing,type_unknown,
> sensitivity_invalid,description_missing,column_unknown,duplicate_column,grain_missing,
> grain_unknown}`, `exception.expired`.
> 
> ## Acceptance tests (`tests/unit/registry/`)
> 
> - Synthetic violations give the same sorted ids on repeated runs.
> - A baselined violation passes; a new one fails; a fixed one is stale.
> - An expired exception fails; an active one suppresses; a missing reason is rejected.
> - Changing preset data changes results with no code change.
> - The check and the CLI run with Spark unimportable.
> - Metadata merge keeps unrelated comments and properties and drops stale owned ones.
> - Sensitivity coverage separates the three states.
> - Packaged defaults hold no vocabulary, tokens, prefixes or suffixes.
> 
> ## Deviations
> 
> None from the shared guardrails.
