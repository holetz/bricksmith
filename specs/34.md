## Problem

`git ls-files -s .claude/quenching.json` reports mode 120000: the file is a symlink to `../.agents/quenching.json`. On Windows without symlink privilege (no Developer Mode, `core.symlinks=false`), git checks it out as a plain text file whose content is the link target path. That file is not valid JSON, so `cq specs config` falls back to `backend: github` and the canonical git spec store on the `quenching` branch is unreachable from that checkout.

## Proposal

Replace the symlink with a regular file whose content is byte-for-byte the same as `.agents/quenching.json`. Add a unit test that parses both files as JSON, asserts they are equal and asserts `backend == "git"`, so the two copies cannot drift silently.

## Out of Scope

Changing the store backend, the envelope schema or any other `.claude/` or `.agents/` content; repository-wide symlink policy.

## Impact

.claude/quenching.json (mode 120000 -> 100644); a new test module under tests/ (for example tests/test_quenching_config.py).

## Validation

`git ls-files -s .claude/quenching.json` reports mode 100644. On a Windows checkout without symlink privilege, `cq specs config` reports `backend: git` and `cq specs list` reads the quenching branch. The new test passes, and fails when either file is edited alone. Full gate stays green on Linux.

## Design

The change is a mode change of one tracked path plus one test. `.claude/quenching.json` becomes a regular file (mode 100644) holding the same bytes as `.agents/quenching.json`. The test reads both files relative to the repository root, parses them with `json`, asserts equality and `backend == "git"`.

## Alternatives Considered

- Keep the symlink and require `core.symlinks=true`: rejected, it fails on default Windows checkouts and is the reported problem.
- Generate the file in setup.sh: rejected, a fresh checkout would still be broken before setup runs.
- Regular file plus drift test (chosen): works everywhere, the test prevents silent divergence.
