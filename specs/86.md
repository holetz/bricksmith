## Problem

Under `autonomous`, step 7 of `/quenching-specs conclude` merges `origin/<base>` into the work branch. Only conflicts in the deployed surface count as mechanical there; any other conflicting path means `git merge --abort` and `needs-human`. During spec 78's conclude (2026-11-23, epic 85 wave), the base had moved by 21 commits. Two sibling specs had each added one sorted line to the same `docs/how-to/index.md` listing, so the merge conflicted on exactly that hunk: HEAD added `feature-selection.md` and origin/main added `feature-store.md`. Resolving it needs no content choice, only the union in sort order. Read literally, the flow stops the whole wave and has the orchestrator relaunch the spawn. The runner resolved it as the union and recorded a `decision:` line instead. That improvisation is the evidence.

Parallel specs in one epic each add a how-to guide, so this will recur on every wave. The improvement should make the outcome deterministic: either `index.md` listings maintained by the knowledge insert procedure join the mechanical class (regenerate or union-sort the listing, then verify that every line points to an existing file), or the stop is kept on purpose and documented as such.
