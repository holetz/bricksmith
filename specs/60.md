## Problem

Reproduced 2026-10-23 by the autopilot conductor on main (af18d01), from the round correctness review (Claude reviewer and Codex, both; range e2742f7..af18d01), against the pre-round module at e2742f7:

- `redact_text('{"health":"http://host:8080/ok","db":"postgres://u:pw@db/x"}')` → unchanged (e2742f7 masked `pw`). Same with `http://h:80/,postgres://u:secret@db/x`. Cause: `src/bricksmith/ops/redact.py:39` `(\S+)` consumes the later URL and `:156` takes `8080/` as a port, returns the match unchanged, and `re.sub` never revisits the consumed text.
- `redact_text('https://user:1234/secret@host/x')` → unchanged (e2742f7 masked it). Cause: `redact.py:156`, a numeric password prefix followed by `/` reads as a port.
- `redact_text('https://u:a@b?c@host/x')` → `https://u:<redacted>@b?c@host/x`; `https://user:p@ss?word@host/x` → `…<redacted>@ss?word@host/x`. Cause: `redact.py:158`, an `@` before `?`/`#` wins, contradicting the docstring's whole-text fallback (`:153-154`).
- `redact_text('https://u:pa/@host/x')` → unchanged. Cause: `redact.py:160` skips every `@` right after `/`, including the real separator.
- Over-redaction: `redact_text('https://u:pw@host/api/users/bob@example.com')` → `https://u:<redacted>@example.com` (also with `host:8080`). Cause: `redact.py:159`, the last qualifying `@` may sit in the path.

Consequence: #54 (PR #33) made passwords print in clear in logs and reports for URL shapes the previous code masked, and still swallows host and path. Keep #54's wins (credential-free `host:port`, `@` in query, `/@alice`), #41's linear-time bound, and add each case above as a test.
