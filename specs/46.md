## Problem

Unmatched rows with null keys are counted but never sampled in cardinality failures.

Reproduction (2026-10-16): `run_check(Check.cardinality("a", expect="many_to_many",
require_match=True), [{"a":None}], [{"a":None}], sample_limit=5)` fails with `unmatched_rows=1`
but `samples=()`; with mixed rows `unmatched_rows=4` while only `{'a':5,'b':5}` is sampled.
Cause: `src/bricksmith/quality/checks_rows.py:51` adds `lnulls` to the count while the samples at
`:59-61` come from `lcounts`, which excludes null keys; `checks_spark.py:65-66` has the same shape.

Consequence: the failure reports rows it cannot show, so an operator cannot find the offending
null-key rows from the result.
