## Problem

`docs/development/specs-migration.md:7` still says `.claude/quenching.json` "points to that same
envelope", describing the symlink that PR #6 replaced.

Reproduction (2026-10-15): `git ls-files -s .claude/quenching.json` →
`100644 ad807cf...` — a regular file with the same blob as `.agents/quenching.json`, kept equal by
`tests/test_quenching_config.py`.

Consequence: a reader following the migration doc expects a symlink and may recreate one, which
breaks the git spec store on Windows checkouts (the failure spec 34 fixed). Proposal direction:
describe both files as regular copies kept equal by the test.

## Proposal

- The migration document describes `.agents/quenching.json` and `.claude/quenching.json` as regular files containing copies of the same configuration.
- It identifies `tests/test_quenching_config.py` as enforcing equal parsed JSON and selection of the git backend.

## Out of Scope

- No configuration, test, runtime, automation or symlink changes: the existing files already implement the required cross-platform behavior.
- No broader documentation sweep: this spec corrects the captured migration paragraph only.
