## Problem

The remote proof that spec `## Validation` sections name (`BRICKSMITH_RUN_REMOTE_TESTS=true uv run --group remote pytest tests/remote/...`) cannot run from a worktree slot. A slot (`../bricksmith-slot-<n>`) carries only `.env.example`, because `.env` is ignored and the worktree setup does not provide it. During the spec 70 conclude on 2026-11-23, step 7 re-ran `tests/remote/test_model_monitoring.py` from `/home/…/bricksmith-slot-2`, and both tests errored at setup with `bricksmith.errors.ConfigError: no profile or workspace host is configured for this context` (`src/bricksmith/clients.py:45`). The run had to improvise: it sourced the main checkout's `.env` into the shell (`set -a; . ../bricksmith/.env`) before the proof passed (2 passed, 17 min). Nothing documents that step, so a run that skips it can mistake a missing context for a red proof, or skip the proof altogether.

The fix has to make a slot able to run the remote harness through a declared, documented route. Options are a `worktreeSetup` step, a harness lookup of the primary checkout's `.env`, or an explicit documented env-file path. It must never copy credentials into tracked files or select a profile implicitly (free-first, one explicit context).

**Insumos**

- `.agents/quenching.json` declares no `worktreeSetup` that provisions `.env`
- `docs/project/databricks-tests.md:40-48,112` covers the `BRICKSMITH_*` variables and the remote run command; it doesn't say how a worktree gets them
- `src/bricksmith/clients.py:45` raises the `ConfigError`
- Spec 70, conclude step 7 (pre-merge gate re-run), 2026-11-23
