## Problem

After `uv sync --locked` (default groups only, as both `scripts/setup.sh` and `.github/workflows/ci.yml` run it), `uv run pyright` reports 29 reportMissingImports errors for the optional heavy integrations pyspark, databricks.bundles, mlflow, sklearn and pandas. They occur in src/bricksmith/dab/adapter.py, src/bricksmith/mlops/*, src/bricksmith/monitor/*, src/bricksmith/quality/*spark.py and tests/unit/dab/test_dab.py:303. Many of these imports already sit under `TYPE_CHECKING` or are guarded by `pytest.importorskip`, which do not stop pyright from reporting them. Those packages live only in the non-default `remote` dependency group and in extras, by design, so the documented gate is red on a fresh clone on every platform.

## Proposal

Make pyright treat the declared optional integrations as legitimately absent in the default environment, while keeping every other diagnostic, including missing imports of anything else, at its current severity. Prefer a narrow, declarative mechanism scoped to the adapter modules or the named optional packages (for example per-module pyright configuration or execution environments) over a project-wide `reportMissingImports = false`. Code that uses these symbols must stay correctly typed when the extras are installed.

## Out of Scope

Adding heavy integrations to default or dev dependency groups; changing CI workflows, hooks or the gate command; changing runtime import behavior or the lightweight root import.

## Impact

pyproject.toml `[tool.pyright]` and/or the listed modules' import guards; tests/unit/dab/test_dab.py. No dependency or lockfile change.

## Validation

`uv sync --locked && uv run pyright` reports 0 errors with default groups only. A deliberately misspelled non-optional import still fails pyright, which proves the suppression is scoped. With `uv sync --locked --group remote`, pyright reports no new errors. ruff and pytest stay green.
